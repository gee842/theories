## A concrete connection between the parallel studies

The [prediction-action construction](PREDICTION-ACTION.md) supplies a formed finite circuit with a paid predictive retrofit. The [protocol-composition result](PROTOCOL-COMPOSITION.md) supplies a general criterion for several physical events to implement one learning operation. This study establishes their connection for the predictor's deterministic, payable-write trial law.

Every completed trial consists of exactly four actual events:

\[
\text{pay retention rent}\;\longrightarrow\;
\text{act and acquire a receipt}\;\longrightarrow\;
\text{pay to write memory}\;\longrightarrow\;
\text{finish and return to readiness}.
\]

An independently stated macro law gives the command, payment guards, learned score, remaining fuel and source, and both remaining hardware lifetimes. Its steps are exactly the completed first-return blocks of that physical law. Finite sequences of those steps concatenate into actual physical histories, with the endpoint of each operation supplying the next operation's entire starting state.

The macro law keeps the full physical state at each boundary and changes the event granularity. It does not yet reduce that state to a smaller sufficient model. Its command and update equations are embedded in the concrete law; no separate controller is introduced merely to rename the same mechanism.

This discharges a local implementation obligation that the generic theorem previously assumed. It does not derive the retrofit recipe, identify all parallel material models, or complete the unified foundation.

## Which memory and command are preserved

The circuit carries a score from zero to four, its last executed action, and an installed update rule. Below the midpoint it commands one route; above it, the other; at the midpoint it retains the previous action. These are fields of the existing physical state. The macro description introduces no additional memory register.

At entry and work, the committed command must equal the circuit's command. After work, it must equal the executed action stored in the physical selector. This distinction matters: writing can change the command for the *next* trial before the current trial has finished. Requiring the old command to equal the newly revised command would incorrectly prevent completion of a corrective update.

The updater is fixed within a trial. Replacing it or reversing the hidden regime are separate ready-state events in the parent model. This trial-only correspondence excludes those events; it does not silently compress a whole reversal or reconstruction history into repeated trials.

## What counts as the observation

The physical action generates a receipt. The write consumes a target decoded from the executed action and that receipt. **Finish clears the temporary receipt.** Reading the finished receipt field would therefore misreport a successful trial as a failure.

For either installed update rule and every valid old score, the two possible targets produce different new scores. Consequently the old score, new score and installed updater identify the target actually consumed by the write. Together with the executed action, they identify its actual earlier receipt. The proof equates this report to the intermediate physical receipt; the reporting function does not inspect the hidden regime.

This is an exact description of the event's causal input. It is **not** a newly built endpoint sensor or a second stored copy of the old memory. Another physical mechanism that needs to read the receipt after completion still needs an actual evidence-retention interface. Nor does reconstructing a receipt make it reliable: identifying the environmental target from it still depends on the parent model's noiseless complementary response law. Outages can make failure ambiguous.

The score bound matters. At the invalid old score five, the Slow updater maps both targets to four, so this particular reconstruction fails. The parent law's bounded-score invariant excludes that state from histories beginning with its declared retrofit.

## Payment order changes which learning operations exist

A completed trial requires live circuit and updater leases, an available source packet, and enough initial fuel to pay retention rent and the work charge. The fuel actually remaining *after* the action's return must then fund writing. A successful return may fund that later write; it cannot pay an earlier bill.

These conditions describe which trials complete. They are not a new pretrial test available to the circuit: completion depends on the actual return, whose hidden cause the circuit cannot inspect beforehand. The physical process can start an attempt that later cannot finish.

The checked examples use the existing primary parameters: rent one, work three and writing one.

| Actual inherited state | What happens |
|---|---|
| Three fuel units, a correct route and an available packet | Rent consumes one; two remain, so work cannot start despite the prospective return. |
| Four fuel units, a wrong route and one packet | Rent and work execute; the failed receipt exists, but no fuel remains for writing. The old score stays unchanged. |
| Four fuel units and a correct route | The action's actual return funds writing, so the trial can complete. Requiring all three bills upfront would wrongly exclude it. |
| A completed failure with only one updater lease unit initially | Completion leaves the updater expired. The next trial inherits that obstruction. |

The unfinished attempts remain actual paid prefixes of the physical law. They have no completed macro step. The finite completed-history equivalence cannot be used to discard them from a probability, reliability or empirical claim.

For completed histories, the earlier exact energy account carries through every micro-event, including unsuccessful source consumption and every cut inside a trial. Each completed trial consumes exactly one inherited source packet. Material and remaining source are inherited; no boundary resets them. The account uses the parent law's admissibility premises and declared costs. It does not derive those costs from chemistry or implement the separate consumable typed-part law.

## What this advances, and what would revise it

We now have an actual example in which a paid physical sequence implements a learned-memory operation with the same subsequent command and the same resource history. The remaining problem is increasingly specific: explain the formation and consequence-dependent revision of the supplied sensing, writing and prediction-to-action routes, then connect their operational predictions to evaluative use and other centers of significance.

The result would need revision if the concrete implementation could take another permitted first-return path, change its updater during the write, carry an unrepresented input, lose the bounded-score invariant, or charge a different intermediate cost. A noisy observation law or runtime recipient would require new interface proofs. These are concrete obligations for subsequent constructions, not consequences of calling both descriptions “learning.”
