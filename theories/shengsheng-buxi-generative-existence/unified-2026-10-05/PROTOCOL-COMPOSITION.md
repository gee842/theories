# When several physical events implement one learning step

6 October 2026. AI-assisted development under the [generative-grounding goal](GENERATIVE-GROUNDING.md). The named connection is **physical construction, sensing and writing → a completed learning operation → further action under inherited conditions**.

## The missing connection

The [previous composition result](CONTROLLED-REFINEMENT.md) preserves a learner across descriptions that use the same event granularity. Actual sensing or updating can take several events. Formation, measurement and writing may each consume support before the resulting prediction can be used. An intermediate failure therefore matters even when the abstract before-and-after description appears affordable.

This study makes that implementation boundary explicit. It complements the concrete formation and prediction studies without supplying another learning recipe.

## Completed physical protocols

A declared protocol starts at a decision boundary, retains one committed command, follows a nonempty sequence of permitted physical events, and completes at the next boundary. Every internal event is part of the actual micro-process. A delivered observation and a decoding of the physical boundary state identify the resulting abstract state and learned memory.

If completed protocols preserve and lift each abstract controlled step from **every actual corresponding boundary state**, then their finite histories preserve the same commands, observations and final decoded memory. Their physical event sequences concatenate into one continuing history. A state reached by one operation becomes the actual input to the next.

The [mathematical companion](../../../_process/research/2026-10-05-generative-foundation-review/root-foundation/PROTOCOL-COMPOSITION-MATH.md) spells out the local obligation. It includes the controller's choice and update equations. Matching fuel balances alone does not establish it, and a stored abstract memory is not treated as free additional hardware: memory is decoded from the concrete boundary state.

The result concerns completed protocols. Interruptions, command changes, external interventions or observations of partially written memory need their own representation when they affect the claim. A completed-step model cannot silently erase them.

## A return cannot pay an earlier bill

In the finite example, one event spends an existing fuel unit; a later event transfers a unit from a finite source. A completed operation restores the usable fuel balance while depleting the source.

With no usable fuel, the net balance still looks sufficient, but the first event is unavailable. With one usable unit and two source units, two operations can complete; both source units are consumed in the same history. No boundary restores spent resources.

The general accounting result preserves the costs and credits actually present in the micro-law and every actual prefix. Upfront affordability additionally comes from that law's payment guards. An accounting inequality alone does not turn future receipts into present fuel.

## An available completion may never occur

A second implementation permits an internal stall as well as completion under the same committed command. It has the same completed-step possibilities as the version without stalling while also admitting a run that never reaches the next decision boundary.

Thus exact completed histories do not establish that an issued action finishes. A decreasing internal rank can limit repeated internal steps, but completion also requires a route out of unfinished states. Probability and elapsed-time claims need their own laws.

There is also a paid deadlock: with one usable fuel unit and no source, entry spends the fuel and reaches a busy state with no next event. This incomplete attempt stays in the physical model and its account, even though it has no completed abstract step. A success-only boundary description cannot be used to erase such attempts from an empirical or probabilistic claim.
