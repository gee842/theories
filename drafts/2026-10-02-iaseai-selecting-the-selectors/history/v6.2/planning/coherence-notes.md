# Coherence notes: applying COHERENCE-A

4 October 2026. This pass applied the integration editor's edit list (`planning/coherence/COHERENCE-A.md`, 32 numbered edits with sub-edits, plus section C's gaps) to `src/`. Before deciding, I read the edit list, the whole assembled core, CLAIMS §8–§9, the relevant TESTS, EVIDENCE, X8, X10 and S5/S9/S10 passages, and the corpus wherever an attribution was in question. All 47 "current" strings were found exactly once, as the list says.

**Method.** One script applied the edits, and it refused to write anything if an old string did not occur exactly once. It ran first on a scratch copy, which was assembled and run through refs and xref, and then on the live `src/`, which had not changed in the meantime apart from the reference lists that `refs_v62.py` regenerates. The live build matches the scratch build byte for byte. In total there were 62 replacements across 20 files: 45 in the core, and the rest in S0, S9, S10, TESTS, CLAIMS and CHANGELOG to keep them consistent with the core.

**Build.** `src/assemble_v62.py` reported no problems (93 core and 35 supplement declarations). `refs_v62.py` reported no problems. `xref_v62.py` reported ALL CHECKS PASS: citations covered in both directions, 32/32 must-stay items present, the guide and §1.2 matching at 9/9 items with every share unchanged, and no state or firm named. I did not rerun `checks_v62.py`: no number changed, and the script does not read the documents. `src/sentcheck.py`, run against the pre-pass THEORY, flags only the expected sentences: the §4.6 paragraph deleted by edit 15, the §5.3 sentence reworded by edit 26, and the Chinese guide, which the tokenizer cannot read and which is unchanged. The core is now 56,197 words, up 98.
