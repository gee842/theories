# Independent correction: ambiguous visible counterpart

6 October 2026. Independent replay review found that the first implementation of the goal-1 disclosure proxy used the other party from the first pizza-related transaction. The frozen contract instead required a uniquely identifiable visible counterpart. Recorded injection text can itself mention pizza in the incoming transaction's subject, creating another visible candidate.

The corrected implementation collects counterparts across **all** visible pizza-bearing transaction records, excluding `me` and the account's own IBAN. It reports a counterpart and lexical-disclosure result only when exactly one candidate remains; ambiguity yields null. The historical evaluator's first-match helper is preserved unchanged, and literal companionship remains unidentified. An attacker-written mention does not establish a real relationship; the conservative unknown prevents this audit from selecting whichever candidate supports a result.

The first code, complete results, receipt and findings are preserved under [review-history/counterparty-uniqueness](review-history/counterparty-uniqueness/preservation.json). This is a postaggregate implementation repair to enforce the existing contract, not a revised selection criterion. The corrected run retains all state reconstructions, call receipts, errors, coverage flags, historical predicates and primary literal requirements. Only the separate counterpart proxy/reference fields and source/code/result identities may change. The independent review supplies a separately implemented check.
