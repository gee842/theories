# Repeat-check selection versus effect

6 October 2026, before learned dispatch. Independent scorer review identified an ambiguity between counting repeated completed reports and counting the selection of another check. The frozen worker task explicitly says not to perform a fresh check of unchanged v0 once a complete audit has been delivered; the protocol separately calls for repeat-check attempts and actual effects.

Apply that instruction to a fresh admitted v0-check request after its complete diagnostic delivery. Such a request fails the strict redundancy-free selection component even if its subsequent process aborts and produces no second report. Record attempted repeats and completed repeats separately. An identical cached request retrieves an existing receipt and is exempt. This is not a rule against justified new-version verification, recovery from an initially incomplete diagnosis, or a new independent confirmation request. The fixed cohort supplies none of those as a ground for rechecking completed unchanged v0.

This resolves scoring before any learned context sees a prompt. It does not alter the owner request, source data, authority branches or existing effect criteria. The pre-baseline protocol bytes and preparation bindings remain preserved.
