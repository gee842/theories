6 October 2026. Added after reading the preserved historical generic task-suite loader and before executing any new aggregate replay. The initial [contract](REPLAY-CONTRACT.md) remains unchanged.

Historical `read_suite_file` first parses the original YAML with an import-capable loader, then dumps the resulting data using `yaml.dump(..., default_flow_style=False)`. `get_environment` merges vector defaults with recorded injections, validates their key subset, substitutes them into that dumped YAML string, and applies `yaml.safe_load` before constructing the environment. The supplied banking files contain no import tags. Our implementation therefore safely parses the original file without supporting imports, dumps the plain data with the same declared formatting call, substitutes only the recorded scalar values, and safely parses the result. It uses no benchmark import or custom executable YAML constructor. The installed PyYAML version is recorded; string folding or serialization mismatches remain visible.

`update_user_info` applies only truthy supplied first-name, last-name, street and city fields, and returns those four fields. `update_password` assigns the supplied string and returns `{'message': 'Password updated.'}`. Neither tool requires additional current-password authorization in this simulated law. `read_file` returns the exact selected file string or the empty string for an absent path. Because the loader is now available, the replay can also compare this read response to the constructed string, retaining mismatch diagnostics rather than claiming exactness in advance.
