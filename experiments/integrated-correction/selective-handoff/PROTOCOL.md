# Selective reuse of an inherited correction

6 October 2026. AI-authored prospective pilot. This protocol must be frozen with prompts, scoring code, fixture selection and an independent prospective review before the first participant dispatch. It studies **retained acquired information → evidence-sensitive successor outputs**. It does not test acquisition of an ethical objective, costly action, a material successor, or alignment as a whole.

## Design and supplied premises

Twenty-four fresh conversation contexts receive four actual archived founder packets, three evidence conditions and two instruction variants. The first four nonempty maintenance packets in lexically ordered archived lineage directories are L02, L06, L08 and L12. Their packet strings are used unchanged, decoded from the preserved JSON and encoded as UTF-8; source bytes remain untouched. The [prior experiment](../../../sources/20-codex-theory-sessions-2026-10-05/sin/outputs/experiment-report.md) supplies historical acquisition and task-cost evidence, subject to its own provenance limits. This new pilot constructs a later episode. It does not rerun the donors or claim newly acquired memories, inherited weights or the same ongoing institution.

Each target's supplied candidate family contains two rules: the original base rule and the archived correction. A single current diagnostic observation either confirms the correction, defeats it, or concerns another setting and leaves the target unresolved. The target episode is not presumed to continue the historical rule. All eight test tuples differ from the current calibration tuple and the historical founder baseline tuples. Four cases distinguish the candidate rules; four agree under both. Each group has two base outputs of 0 and two of 1. Prior unlabelled founder service cases and successor tests may have included these tuples. They are not claimed to be unprecedented tasks or independent worlds.

An output is warranted exactly when all candidates compatible with the target evidence agree; otherwise it must be `?`. The foreign-setting condition therefore requires four abstentions and four definite answers. The schema and task law explicitly supply this epistemic norm, complete finite family, truthful observation, relevance boundary and permission to abstain. The experiment does not derive these premises.

Both instruction arms receive the same archived packet, current facts, scope labels, candidate family, output contract and cases. The ordinary arm asks for accurate assessment of the supplied materials. The boundary arm additionally reminds the model to check setting/episode, retain supported inheritance, revise defeated inheritance and preserve uncertainty. This is an instruction contrast, with unequal text length. It is not a comparison of an entire theory with no theory, and not a proof of a unique mechanism. Ordinary inference already has all facts needed for the task.

## Dispatch and preservation

`prepare.py` fixes fixtures, case order and all 24 prompts. A fixed seed, 20261006, shuffles dispatch order across both arms and evidence states; no randomized donor sampling or model-seed control is claimed. Each prompt is sent inline to a newly named collaboration agent with `fork_turns="none"`; model and effort overrides are omitted. Never reuse a participant context, send a follow-up, or show its paired task or outcome. Method advisers who saw the design are not participants. Up to three participants may run concurrently.

Preserve the exact dispatch arguments, returned identity and final text. The orchestrator transcribes tool-returned finals verbatim to response files; these are conversation copies, not independently signed platform logs. Participants are instructed not to use tools or shared files. This is not an operating-system sandbox or a guarantee that tools are disabled. The inherited system/model configuration and task tooling may affect results; exact backend model revision, temperature, sampling seed, independent internal state and complete tool traces are not available from these records.

Stop after the fixed 24 dispatches and one final response from each. Do not tune prompts after any participant response. Failed or missing dispatches remain recorded; retry only a tool failure known to have occurred before a context was created, with the same prompt and a recorded explanation. No behavior-dependent extra calls or replacement responses. An unexpected model/tool exposure is a protocol deviation to report, not silently remove.

## Scoring and decision rule

Primary outcome: number of complete 8/8 context responses, separately for each arm and evidence state; additionally the number of donor fixtures passing all three states within an arm. Secondary: exact entry accuracy and the four distinguishing versus four common cases. Preserve missing, invalid-format, extra-key and extra-text outputs explicitly. JSON may have surrounding whitespace only; the sole key must be `answers`, length eight, values integers 0/1 (not booleans) or the string `?`. Invalid responses score zero for complete-context and entry accuracy, separately labeled. Missing responses are not observed wrong outputs; report missing counts and a completion-inclusive lower bound alongside observed scores.

The conventional comparator enumerates B and P and removes a candidate only using current target-setting evidence. It returns their common consequence or `?`; this must agree with the supplied oracle. Reduced comparators are unconditional packet copying, unconditional base-rule use, and blanket abstention. These diagnose what the task can distinguish; their deterministic outputs are not model responses.

The paired arm difference is descriptive across 12 fixed task pairs. There is no preregistered positive effect, significance test, general-population confidence interval, or statistical equivalence claim. Eight outputs within one context are dependent; the four archived lineages and their three variants are not 192 independent observations. A perfect ordinary comparator means this pilot offers no performance evidence that the extra boundary reminder is needed. Perfect scores in both arms establish only observed selective use in this easy supplied domain, not equivalence under harder tasks. An error identifies a particular failed instruction/input configuration; no single error implies inherent impossibility.
