## 2. Operational relation, separately from a desired decision

The native relay setting is `r ∈ {0,1}`. A weak challenge produces the actual
response `f(r)`. All four static laws are included: `00` no supported route,
`01` relay-dependent, `10` relay-obstructed, and `11` relay-independent. These
names describe the entire response pair, not producer-side goal labels.
The controller receives no `f` or classification. The actual relay, transient
response, acquired slots, final load stock, and audit metadata are distinct.

The low-power/full-load correspondence is supplied: within the same context,
the later transfer succeeds under exactly the settings that responded to the
weak test. The tests consume actor work but do not debit the source packet or
perform full-load service. A distinct final transfer tests the enacted setting.
Changed full-load response and changed context are included as counterregions;
two weak tests do not establish universal calibration or future stationarity.

Primary context is 1. A receipt is `(context, issued setting, response)`. Missing
contact, an explicitly wrong setting/context, and a non-bit response are not
negative responses. Deliberately undetected false bits remain a corruption
control, not successful acquisition. The declared tests are setting 0 followed
by setting 1; the choice of this identifying schedule is supplied.

A successfully charged contact clears its native pending datum even when the
reported contact is missing or corrupt. A denied contact leaves the pending
datum intact. Slot writing is attempted and charged even for a missing or
misbound datum; it records unknown in that case. Wrong-context/setting and bit
flips alter the returned datum only. An uncharged observation is never exposed.

Install; for each setting issue `relay_command`, challenge, contact, then write
its slot. Only correctly bound valid contacts become acquired values. Read both
slots and commit a choice. With both slots known, choose 0 if it responds, else
1 if it responds, else record `no_supported_route`. With either unknown, record
`unresolved` and do not issue service. Preference for bypass when both respond
is a supplied local preference for less maintenance, not universal optimality.

The matched `clamped` consumer incurs identical installation, tests, contacts,
writes, read and commit charges, and preserves the acquired pair. It instead
keeps the old component-complete stop. The ordinary `conventional` consumer
implements the same decision from the same acquired pair by a separate
truth-table lookup; it must match the learned consumer's entire result.

When service is selected, issue the chosen relay command again, enact its hold
or release, then attempt full-load transfer. Source availability is checked
before charging transfer. Exactly 10 source units enter a separate load stock
on success or waste on failure. There is **no actor income**. No final receipt

actual final fulfillment belongs to the physical state/audit. It must not be
reported as an acquired completion judgment. Finally attempt retention of all
live cells, even after a failed earlier operation. No refund or source reset.
Retention is attempted only if installation succeeded; an installation failure
preserves the inherited retained interface. Within an account charge, capacity
is checked before fuel. Source availability precedes the transfer charge.
Unknown, absent and failed conditions never silently become a zero response.
