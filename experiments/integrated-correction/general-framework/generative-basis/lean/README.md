## Reproduce

Run `python3 check.py` from this directory. The script uses the [pinned Lean 4.29.1 toolchain](lean-toolchain), the standard library, and no external package. It copies the sixteen sources into a temporary build and compiles their actual dependencies there, including the public entry point. Local compiled objects are ignored and cannot substitute for those frozen sources. The command replaces only this development's verification record and compiler logs. The [original four-module checker and evidence](verification-history/2026-10-06-before-model-integration/manifest.json) retain their exact bytes and original path metadata.

[verification.json](verification.json) records source and compiler hashes, compiler version, audited declarations and their dependencies. The checker rejects warnings, incomplete proofs, custom axioms, unsafe declarations and native decision shortcuts. Every current audit must be empty, including direct audits of seven root definitions. All original 179 audit names are retained; fourteen modules keep their exact bytes, and the two repaired modules retain their original declaration contracts. All 200 finite law inputs and ten support/selector inputs are checked against the archived definitions. The [preservation manifest](verification-history/2026-10-06-before-axiom-removal/manifest.json) retains the exact prior sources and evidence. Each new run saves its own sources, checker, logs and receipt before updating the current receipt.

The source grammar and checker are not themselves a new trusted prover. Trust rests on the recorded Lean compiler and its standard foundations. All imported project definitions are compiled from the recorded source. The formal interface has no finite-state restriction, but its general representation theorem concerns finite existential histories. The infinite claims are the separately proved reserve obstruction and the explicit supported witness.

## Historical replay

For a companion checker that pins the pre-repair structural sources, run from the repository root:

```sh
python3 experiments/integrated-correction/general-framework/generative-basis/lean/replay_before_axiom_removal.py core-tree
```

The helper checks the preservation manifest, copies the Lean subtree into a temporary repository view, restores the archived files, and runs the unchanged selected checker. It saves a replay receipt and compiler logs under `legacy-replays/` and verifies that current source/checker/receipt/log bytes were not changed. It does not relax old pins or migrate the companion's proof dependencies. Supported selections are `core`, `sufficiency`, `core-tree`, `receipts`, `acquisition`, `connected`, `applicability`, `nondual` and `pretraining`; each uses its own original result scope. A changed companion source can still correctly fail its original contract.

The [verified core/tree replay](legacy-replays/1791275071482105000-core-tree/replay.json) passed its original 31-module / 400-audit contract and left current artifacts unchanged. Its original named dependencies remain recorded. This is the representative compatibility replay performed in this round, not a claim that every selection was rerun.

Current inquiry and finite-inquiry checkers pin immutable successful parent-run receipts, so rerunning the default or parent checker does not invalidate their evidence baseline merely by changing a timestamp. The full project sources are nevertheless checked and freshly compiled on every run.

## Scope

The word `Feasible` means existence of an admitted path, not an actual actor's guaranteed power under limited information. No stochastic law, physical identification, ethical scalar, unavoidable learning, historical two-attractor classification, or full derivation of concern is established. The witness's mechanisms remain supplied. This is a verified realization of the candidate's stated causal commitments, with explicit limits, not a theorem produced by defining a predicate called “candidate.”
