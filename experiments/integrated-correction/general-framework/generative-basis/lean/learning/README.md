# Consequence access, selector revision and paid continuation

AI-assisted development, 6 October 2026. This package advances the named bridge
**consequences → revision of selectors**, under the repository's
[generative-grounding goal](../../../../../../theories/shengsheng-buxi-generative-existence/unified-2026-10-05/GENERATIVE-GROUNDING.md).
It supplies universal necessary conditions, a paid feedback witness, and an
actual-state support interface to the existing formed-variant construction.
The origin of a learning or update architecture remains an open derivation.

## Universal information interface

`ControllerRevision.lean` quantifies over arbitrary world, memory, action and
observation types. A supplied deterministic controller chooses an action from
memory and revises its memory from the resulting accessible observation.
`closedLoop` requires an actual world transition, the chosen action, the
observation of that predecessor/event/successor and the actual updated memory.
Every finite history retains these intermediate states; no episode resets them.

The main results establish:

- A valid closed-loop trace projects to a valid world trace.
- Its memory and issued commands factor through its initial memory and complete
  feedback history. Two valid histories with the same initial memory and the
  same feedback therefore have identical final memories and command sequences.
- If two terminal world conditions require incompatible next commands to admit
  their specified future action words, identical feedback cannot support both.
  Conversely, achieving both such possibilities requires a feedback difference.
- Restricting a world process by a controller preserves an independently
  justified `SustainLaw` on that world, through the actual world-state projection.

The incompatibility statement uses the core's actual `Feasible` relation. Its
future word is an analyst's comparison task, with no path from that task to the
controller's update. A wrong command can be physically executable yet destroy
the required continuation. Feasibility is existential admissibility, so this
does not prove control, adversarial robustness or success under every outcome.

The feedback history must include **all inputs that can affect the update**:
resource readings, direct physical channels, clock information and other inputs
cannot be silently omitted. Actions are generated by memory in this interface;
an external action override would need an additional input. The result is for
deterministic controllers. It does not assert stochastic equivalence from
matched observations or make a statement about unrelated random outcomes.

## A jointly paid feedback witness

`FeedbackExamples.lean` supplies one finite law with two hidden modes. A probe
reveals the mode through a property of its actual successor. A fixed supplied
update stores that observation, selects left or right, and then attempts use.
The correct response makes use possible. Both responses can execute; the wrong
one creates a dead state. Every event consumes one unit of the carried reserve,
including probing. There is no replenishment.

Lean checks a complete probe/response/use trace in both modes and proves that
any three-event trace requires at least three initial units. The same process
satisfies the general support account, so information and resource conditions
are instantiated together. The unit charges are declared event costs; they do
not derive microscopic sensing costs, hardware formation or memory maintenance.
The controller and both response mechanisms exist at the start of this witness.

The checked failures retain distinct explanations:

- With the probe blinded, **any deterministic controller, of any memory size**,
  receiving that same one-event observation history cannot support later use in
  both modes. The theorem is instantiated using actual blind-probe traces.
- Inverting the probe signal yields a valid two-event history into the dead
  state, even though one unit remains. Resource sufficiency alone cannot repair
  misleading feedback under this update rule.
- A prepared state with no reserve cannot execute use. A stored structural flag
  alone does not establish an enabled capability.
- The same current empty signal can preserve different memories inherited from
  earlier observations. Equality of current signals alone does not imply
  equality of the complete accessible history or memory.

This is a conditional witness of consequence-sensitive response. The update
architecture is fixed, the feedback mapping is supplied, and the probe reports
the mode directly. These results neither derive endogenous selector formation
nor show how a system discovers, tests or repairs its observation mapping.

## Actual support bridge for formed alternatives

`FormationSupport.lean` imports the established
[formed-variant law](../../../../../shared-renewal-capability/regulation/retention/formation/README.md)
and its exact root representation. It proves usable, local, source and closed
accounts and transports each actual history into `SupportTrace` with the same
event word and intermediate resource-bearing states. Capture credits usable and
local reserves by drawing from the finite source; it does not credit the closed
account. These are operational quantities, not scalar welfare or supplied reward.

The bridge bounds local copies by initial local fuel plus source, requires
actual capture before positive local expenditure from an empty local store,
and proves that a full-state cycle can neither spend energy nor draw down the
finite source. A prefix handoff inherits the actual intermediate stocks.
The existing formation/repair/capture/copy witness uses four initially usable
units plus one captured unit; after repair, only one source unit remains, and
after the paid copying endpoint no further positive expenditure or capture is
possible. Several resource identities also appear in a concurrent same-law
formation study; repeated proofs of that law are not independent evidence.

The controller witness and formed-variant law are different constructions. The
resource bridge does not prove the formed-variant process implements the
controller, nor does it by itself construct a selector or evaluate one.

## Reproduce and audit

### Controller-compatible refinement extension

`ControlledRefinement.lean` adds a separately checked connection to the causal
core: exact world steps plus compatible complete observations preserve and lift
finite histories of the same supplied controller with its actual inherited
memory. Both the world and observation interfaces compose. A countermodel drops
a hidden bit while preserving all uncontrolled action possibilities and unit
fuel costs; after a probe, the dropped information changes the next command.
No deterministic channel on that erased state reproduces both bit values.

This is sufficient for the stated action/observation-labelled finite-history
contract, not necessary for every controller's action-only behavior. The same
action vocabulary and step granularity are required. Probability, robustness,
hardware origin and any omitted sensing or writing costs are not inferred.
The [canonical account](../../../../../../theories/shengsheng-buxi-generative-existence/unified-2026-10-05/CONTROLLED-REFINEMENT.md)

five use only standard `propext` and/or `Quot.sound`. The separate
`controlled-refinement-audit.txt` records compiler output, exact declarations,

### Paid protocol composition extension

`ProtocolComposition.lean` defines nonempty first-return physical blocks under
one committed command, their concatenated realizations and their actual boundary
reports. A local contract with the existing closed-loop process decodes world
and memory from actual physical boundary states; it does not add a free record.
Finite controlled histories then correspond to completed physical realizations.
The same micro-event account bounds completed histories and each actual cut,
including cuts inside a block. Separate rank results bound internal paths and
exclude an infinite internal execution under strict descent. They do not prove
nonblocking, scheduling, physical time or completion from a deadlocked state.

`ProtocolExamples.lean` separates guarded payment from later receipt of a finite
source unit. Two blocks deplete source from two to zero; a further paid attempt
deadlocks. Stalling and nonstalling versions have the same completed macro
histories, yet the same committed internal tick can admit an explicit infinite
busy execution. Those incomplete attempts remain in the micro-law.

### Concrete prediction protocol

`PredictionProtocolBridge.lean` imports the actual `PredictionAction.lean` law.
Every completed trial is exactly rent/work/write/finish; an independent arithmetic
macro law matches its command, sequential guards and endpoint. Finite macro
histories flatten to actual physical histories, using four micro-events and one
inherited source packet per trial. Whole and prefix energy accounts retain every
actual intermediate state. The macro law keeps the full physical boundary state;
it changes event granularity without claiming a smaller sufficient state model.

`PredictionProtocolObservation.lean` proves that bounded before/after score and
the installed updater identify the target actually consumed by writing. With the
executed action they recover the actual intermediate receipt, even though finish
clears it. This semantic trace report is not a new physical sensor or a free
retained copy of earlier evidence. The reported arithmetic law has exactly the
same completed finite histories as the instantiated physical protocol.

Checked examples retain paid rent/work aborts, an acquired but unaffordable write,
a return that funds later writing, completion into updater expiry, and a changed
future command while the current trial retains its executed action. Macro guards
characterize completion, not a runtime oracle that prevents failed attempts.
Only deterministic payable-write trials are covered; ready reversal/reformation,
full executable outages, skipped writes, rebuilding and stochastic claims are
outside this contract. Retrofit recipes and physical evidence delivery remain
supplied or unresolved.

Run `python3 check_prediction_protocol.py` here. The separate
`prediction-protocol-audit.txt` passes **38 new theorem audits** in a fresh Lean
4.29.1 build of twelve frozen modules: fifteen bridge and twenty-three observation
results. Nineteen have empty axiom dependencies; the other new declarations use
only standard `propext` and/or `Quot.sound`. Predecessor audits separately disclose
`Classical.choice` where present. Source, checker, compiler and toolchain hashes
are recorded. The [canonical result](../../../../../../theories/shengsheng-buxi-generative-existence/unified-2026-10-05/PREDICTION-PROTOCOL.md)
links the mathematical specification and separate internal review.
