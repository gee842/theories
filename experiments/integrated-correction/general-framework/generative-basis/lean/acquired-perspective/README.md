# Acquired perspective verification

The [Lean bridge](../AcquiredPerspective.lean) proves that the already constructed, retained score acquires action-effect knowledge, is corrected from actual feedback and changes a subsequently executed paid command that supports the same organization. The [research note](../../../../../../_process/research/2026-10-05-generative-foundation-review/history/root-foundation/SELF-ACQUISITION-BRIDGE.md) states the precise scope and remaining premises.

Run from the repository root:

```sh
python3 experiments/integrated-correction/general-framework/generative-basis/lean/acquired-perspective/check.py
```

The checker pins imported sources and earlier verification receipts, rebuilds 25 modules in a fresh temporary directory under Lean 4.29.1, matches all inherited dependency audits exactly and audits every new theorem. It also checks that source bytes and baseline receipts remain unchanged through compilation. [verification.json](verification.json) and [the bridge log](verification/AcquiredPerspective.txt) report the exact dependencies. The bridge has 21 audited results; the [composed model entry](../GenerativeAcquisitionModel.lean) adds three actual-history composition results. These 24 acquisition audits contain six empty dependency lists and eighteen inheriting only `propext`; they add no dependency outside the original model's imported chain. The existing structural and outcome modules retain their own source and per-declaration dependency guarantees. No custom axioms or new physical event laws are introduced. Inherited law choices and recipes remain explanatory inputs.

The actor/recipient results compare the existing interface; they do not compose a new physical recipient history or generate the original target labels. The analytical readout for both possible actions is not new runtime hardware. The existing `.work` event executes the current command, and the actual post-correction command is proved enabled and used.
