# Material passport and lifecycle ledger

`index.ts` exports a version 1 material account independent of the animation world. `createMaterialLedger` opens a finite inventory. `applyMaterialEvent` accepts one typed, revision-checked event and returns a new state. `assertMaterialLedger` checks identity, custody, qualification, event order and a per-material mass balance. `materialBalances` reports opening and received input against active assets, available process lots and explicitly unrecovered process output.

An asset ID follows direct reuse. Installation clears its qualification; removal sends it to inspection, where current measured evidence must qualify the same ID before another reservation. Damage can instead lead to repair, quarantine or feedstock. The implemented repair is mass neutral and returns the asset to inspection. Steel feedstock can be recycled into a separate lot and reforged into a **new** asset ID whose passport lists the input asset lineage. Both process steps record input and output mass, declared yield, energy, provenance and unrecovered mass. Reforged output starts unqualified. The `fastener-set` and `temporary-work` kinds use the same custody and disposition rules as primary members.

`runBeamMaterialLifecycle()` is a synthetic example: `steel-beam-001` is installed at A, inspected and directly reused at B, then damaged, quarantined and sent through an assumed recycling/reforging chain. `steel-beam-002` has a shorter type and is installed at C after a new synthetic inspection. The fastener set and temporary brace are separately installed, recovered and requalified in each configuration. The opening steel mass is 115.3 kg; the final active assets total 110 kg and recorded unrecovered process output is 5.3 kg. No external material is silently added. The `measured` inspection entries in this fixture are invented inputs used to exercise the gate. They are **not** physical measurements. The 90/93.3 recycling yield, 88/90 reforging yield and energy figures are assumptions, not validated industrial performance.

The simulation reducer can supply `source: { executionEventId, worldRevision }` on material events and commit them alongside its domain events. `expectedRevision` rejects stale ledger writes; `observedIntegrityRevision` rejects stale inspection and repair evidence after installation, damage, removal or repair. The caller must still check the source world revision and ensure paired domain/material commits are atomic. This module does not size members, validate connection capacity, model energy emissions, prove physical recycling yield or enforce a complete bill of material for a building. Its screening capacity field only gates allocation against a declared role; structural stage checks remain separate.

Run `npx vitest run src/material/material.test.ts` from the demo directory. The tests cover the lifecycle balance, unchanged ID on direct reuse, new ID and ancestry after reforging, fasteners and temporary work, mass-neutral repair, and rejection of mass creation, inconsistent yield, unqualified reuse, assumed qualification, stale inspection and stale ledger revisions.
