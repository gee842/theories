# Constructive succession protocol

This exploratory synthetic study tests paid construction and inheritance across four successor generations. The initial NAND language is already capable of expressing every three-input Boolean function without the study's 32-gate limit. The experiment concerns access under a fixed interface and budget. It does not invent new purposes, prove unrestricted novelty, or model endogenous authority.

## Computation and chronology

All learners use the same bottom-up NAND synthesis routine. They see eight paid target input-output examples. A proposed gate costs one work unit to construct and eight to evaluate on all inputs. The learner keeps the first measured representative of each truth function. Duplicates still incur evaluation costs. Any changed program requires a separate eight-row verification, one installation unit per gate, and an affordable handoff. Programs may contain at most 32 distinct NAND nodes. Queue operations, source traversal, archive ranking and bookkeeping are free in this model; the work units are a declared computational accounting scheme, not measured runtime or physical energy.

Every successor receives a serialized package containing actual source nodes and only paid cached truth tables. No earlier learner, full search arena or discarded semantic dictionary survives. All can inspect the complete successful source and use its subexpressions. Extra roots must carry their full transitive dependencies. Matching an inherited function is recorded as reuse; an installed new composition is recorded separately. Exact verification is cached deterministic computation, not noisy empirical evidence.

The first task is XOR of the first two inputs. A common initial 1,000-unit endowment finances service, synthesis and initial transfer. Ordinary service costs 16 per generation. Subsequent external work flows are either 300 or 1,200 per generation and are the same for all paired arms. Unspent work carries forward without reset or decay. Failed tasks do not terminate the lineage; the previous installed artifact continues operating. Meeting a new task and continuing old service are distinct outcomes. The base language, search procedure and operator competence are supplied and persist identically in all arms; the experiment does not explain their reproduction.

## Inheritance policies

Every policy transfers the installed source and its cached tables for two units per NAND node. Additional source costs a declared archive price per distinct extra node; cached tables cost another one per node. Shared dependencies are charged once. Extra retention can consume at most half the work remaining after the successful source transfer, and at most 16 additional roots are selected. Extra roots whose truth function is already a successful-source subexpression are excluded.

- Solution transfers only the successful source and its cached computation.
- Closest prioritizes available functions with smallest truth-table distance from the current task.
- Diverse computes a greedy ordering by separation from successful-source functions and earlier ranked candidates, then retains affordable roots in that order. Skipped candidates still influenced this precomputed ordering; this is a heuristic, not an optimized diversity set.
- Recent prioritizes the most recently discovered available functions.
- Diverse recompute chooses by the same diversity rule but transfers no cached tables for additional source nodes. The next learner can reevaluate them at eight units each, stopping recovery when an already known or recovered function matches the task. Otherwise recovery is eager and can consume work on irrelevant components. This arm tests a different paid package, not precisely matched archive content, because the retention affordability constraint changes.

All selection uses the current generation's paid records only. There is no future target argument to the transfer function. The archive-price grid is 0, 2 and 16, applied to extra source storage; installed-product source has the same fixed transfer cost in every arm. These are separate cost assumptions, not a universal physical pricing law.

## Future tasks and controls

The four subsequent targets either repeat XOR, independently flip one uniformly chosen truth-table bit each generation, or are drawn uniformly and independently from the 256 functions. Related and independent sequences use 64 paired random seeds, 0 through 63; the repeat condition is deterministic and is run once per configuration. Their outcomes are reported separately. Local tasks favor local similarity by construction; independent tasks do not imply an unrestricted future.

The main measures are completed tasks, completion after previous failures, genuinely new installed compositions, inherited exact matches, paid work and delivered successor material. Four successes on finite tasks cannot establish indefinitely sustainable discovery. Sources, caches, resource balances, correctness and precursor removal receive separate mechanism checks.

The grid also compares no search reserve with reserving one quarter of post-service work beyond mandatory successful-source transfer. The reserve constrains search and cache recomputation; a verified installation may use it. All inheritance arms, including solution only, receive this same reserve rule. Unspent reserve carries forward as resources, so archive retention competes with saving work. Bootstrap uses no reserve so all first-task construction histories match before inheritance decisions.

This protocol is exploratory. Initial bare NAND enumeration checked expressibility of the first task. A five-arm development run on independent seed 0 at flow 1,200 and archive price 2 showed that spending search down to the mandatory transfer floor could leave almost no extra work to inherit. This prompted the reserve comparison above; those original runs are retained in development.json. The revised protocol was specified before the main grid. No held-out or preregistration claim is made. Code and protocol snapshots accompany results.
