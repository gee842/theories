## Single-use provenance and interruptions

The module is tied to the verified parent endpoint before any prior command import. It does not infer acquisition origin from `last=1`. The read interval is coherent under the supplied finite recipe: an instrumented controller write or context/publication/destination replacement retires origin permission and clears cached approval. Paid partial work remains. There is no hidden free register reread after approval.

Immediately before any actual import attempt, origin and the comparison permit are consumed. Trial feedback, later old-archive replay and the current flag value cannot rearm them. Reuse attempts after import, trial and replay are explicit checks. The early-import control deliberately bypasses the certified route, executes the real paid parent import, observes inspection refusal, and can still act through the already imported ordinary port; that action is never counted as certified approval.

The naive post-import ablation pays for its comparison but deliberately ignores origin. It records no independent-evidence status and can corroborate the actual wrong imported command. This preserves the distinction between refusing an invalid provenance claim and undoing an action route that has already bypassed the guard.

The result fields `independent` and `independent_agreement` mean the runtime's **pre-import origin condition**, not a proof that the register escaped all faults or that two channels are statistically independent. Their sound interpretation also requires the declared acquisition/integrity premises. Common corruption can bypass those premises while leaving the runtime origin flag apparently valid.
