# From an actual recipient event to a paid factual cache

This producer connects the [identification mechanism](../README.md) to three
physical four-bit records and a paid, context-tagged factual cache. The
archive reads the actual temporary acquisition register while that query is
running. It never reconstructs runtime evidence from the program's saved
observer trace, and never calls the earlier recorder's different receipt law.
The [protocol](PROTOCOL.md) fixes the preparation, prices, bindings and scope.

The complete original `R,A,R,A,R` controller sequence remains. Protected
archive or cell shortages leave fixed addresses empty while the core continues
under its original law. Exact comparisons preserve the complete projected
five-query histories—actions, receipts, statuses and before/after states—as
well as endpoint distributions. Charging archive work to ordinary working
fuel is a separate intervention that changes that law and can prevent later
queries.

## What was actually constructed and paid

The unchanged formation event table executes the named 44-event preparation
from material28, common91 and source144. Twelve record cells and one reader
are then assembled from formed pairs; the remaining two constituents enter
the old controller adapter. Whole construction costs44 and leaves common61,
source130. A saved routing event, **before the prefix**, allocates working26,
archive15 and reader20. The old prefix can spend only working26. No resource
is replenished at the recording boundary.

This is a feasible controlled preparation, not the original stochastic
two-constituent preparation. Its old success probability2/9 is not imported.
All reported probabilities are conditional on this new construction and
include every subsequent prefix endpoint, including ineligible circuitry.
Prefix spending/loss are the imported conditional ledger marks; the package
does not present them as independently reconstructed individual microhistories.

At each actual paid recipient sense, the bounded physical query pointer
advances. If the fixed address and archive budget permit recording, binding1
locks context and issued action before work and reserves four write units.
The unchanged core work and receipt happen once. Its paid acquisition fills
the temporary `Option Bool` register, which feeds the archive latch; the core
then consumes and clears its temporary register. Four separately paid guarded
writes create `(context,action,present,receipt)`. A completed cell cannot be
written again. Missing and zero receipts remain different records.

Actual factual decoding costs14: activation1, current-context observation1,
and three four-cell reads costing4 each. It produces a three-entry cache and
leaves reader6 for a separate consumer. The prebound orientation queries are
`Z=0, Z=1, Z=0`. A current positive receipt licenses `Some(action==desired)`;
all zeros, absent or partial frames, missing channels and stale bindings give
unknown. A positive receipt for the opposite action can give `Some False`.
The runtime decoder does not read the hidden orientation.

## Results and boundaries

The strict original identification-and-later-use history, three completed
frames and a complete correct factual cache occur with probability **9/64**
conditional on the new construction. Both implementations of the original
variable-coupler prefix match exactly. On the primary witness, the actual
recipient reserves20, working fuel ends4 and reader funds end6. The full
account is

`235 = construction44 + prefix78 + core suffix44 + suffix loss10
       + archive15 + factual decoding14 + retained30`.

The cache is either `[unknown,false,true]` or `[unknown,true,false]` on the
two symmetric strict paths. The first query's failed receipt remains unknown.

| Intervention | What fails or remains |
|---|---|
| Archive14 or eleven cells | The third frame is unavailable; the original core histories are unchanged. |
| Reader13 | All three frames can exist, but only two reads complete; no completed cache is published. |
| Missing receipt channel or no opportunity | Paid frames exist, but none supplies an orientation certificate. |
| Interrupted first write | Two cells and two escrow units remain pending; no later frame reuses them. |
| Context changes during binding | The pending frame remains physically present but invalid; funds are not refunded. |
| Context changes before reading | Historical frames remain; current decoded entries are unknown. |
| Corrupted action tag | Paid complete records can produce false factual entries: expected count **33/64**. Integrity is a premise. |
| Archive charges taken from working fuel | Later core work can become unaffordable; this is not an unchanged-core comparison. |

Record completion and reader completion have separate metrics. Reader shortage
preserves the strict recorded history with probability9/64 but gives no strict
factual-output history. Stale or corrupted records likewise cannot be promoted
to the claimed current correct input merely because all bytes were written.
