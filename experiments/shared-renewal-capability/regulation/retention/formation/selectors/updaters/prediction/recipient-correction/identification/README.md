# Paid identification from positive recipient receipts

The model carries actual formed-coupler histories into a finite diagnostic
protocol. A paid zero receipt leaves the recipient rule unknown and changes
the next exploration action. An acquired positive receipt qualifies that
action under a stable target and a plant without false-positive returns.
The same memory then controls a later paid recipient action. This supplies a
narrow identifiable input to the [recipient interface](../README.md), whose
earlier failure-as-complement decoder is ambiguous during source outages.

The new [protocol](PROTOCOL.md) deliberately supplies an atomic setup recipe,
whole-query prepayment, target reporting, no-false-positive response law and a
five-exposure hold. It preserves predecessor q and last until paid recoding;
then q stores actor bit and recipient candidate, while the old last-action bit
becomes qualification status. Eight codes fit within the inherited ten-state
capacity. The old last-action semantics and parent wear law cease during this
finite interface. This is an explicit successor protocol, not an exact
refinement of the parent's partial-payment setup or query law.

All thirteen source packets are declared before original preparation. Eight
go to the unchanged prefix and five to the new `R,A,R,A,R` schedule. Each
query costs eight actor units, including escrowed acquisition and two writes;
recipient gains stay in a separate reserve. Controller inputs never include
the hidden response rule, true availability, analyst flags or phase number.
Actor calls retain their actual inherited bit; eligible histories with a wrong
actor bit remain in the accounting.

## Exact finite results

Every probability below includes failed preparation and ineligible endpoints.
The primary recipient opportunity probability is 3/4; the prefix and actor
opportunities are noiseless. The positive controller and conventional finite
state table have identical complete distributions in every case.

| Quantity | Positive-witness rule | Failure-as-complement rule |
|---|---:|---:|
| Primary strict unknown → positive identification → later productive use | 1/32 | 0 under this specific history predicate |
| Primary expected recipient captures | 11/96 | 11/96 |
| Primary final false qualification probability | 0 | 7/288 |
| Primary expected wrong qualified recipient commands | 0 | 1/72 |
| Noiseless strict history | 1/18 | 0 under that predicate |

The zero strict count for the failure-label comparator is not a claim that it
cannot act productively: it calls the first failure a qualification, and the
strict predicate requires that failure to remain unknown. Primary captures,
actor reserve and bills are equal. The improvement here is soundness of the
declared qualification under outages, not a general resource-performance gain.
In the same-law case, never exploring gets **5/24** expected recipient captures
against **3/16** for the positive explorer; paying to alternate after an outage
can delay a response that was already correct.

No opportunity and missing channel produce no qualification for the positive
rule. Missing evidence holds the candidate; it is distinct from an acquired
zero. With write price four, qualification still occurs with probability1/24
but no qualified later query can be afforded. A target change after earlier
identification produces **1/24 expected wrong qualified commands** for the
positive rule: stability is a real premise, not a conclusion of one success.

The actual primary witness enters with fuel28, after old prefix spent68 and
lost10. Paid setup leaves24; five calls leave actor fuel
`16,18,10,12,4`, recipient reserve20 and no source remainder. Its complete
161-unit ledger is `preparation4 + adapter1 + prefix68 + prefix loss10 +
suffix44 + suffix loss10 + actor4 + recipient20`.
With a correct inherited actor bit and available actor packets, all five
calls require entrance fuel at least26. At25, the second actor query cannot
prepay; fuel7 and the already acquired recipient reserve10 remain. This is a
conditional route boundary, not a guarantee for every eligible predecessor.

## Artifacts and scope

Run `python3 model.py` then `python3 check.py` in this directory. The generator
uses exact fractions. [fixtures.json](fixtures.json) preserves original
preparation and predecessor masses, states and ledger marks;
[results.json](results.json) contains all suffix paths, microstates, endpoint
distributions and metrics. [check.json](check.json) records source/data hashes,
replay checks and focused boundary checks. The separate independent checker
and [formal package](formal/README.md) have their own validation scopes.

No finite all-zero observation word gives a total zero-error identification
rule: mismatch and outage can produce the same accessible record. Positive
evidence supplies a one-sided qualified label; unresolved remains possible.
An opportunity-floor tail bound requires that the requisite matching trials
are actually completed and paid. There is no infinite source, record renewal,
permanent hardware hold, physical construction of the supplied recipes, or
ethical conclusion from this finite identification result.
