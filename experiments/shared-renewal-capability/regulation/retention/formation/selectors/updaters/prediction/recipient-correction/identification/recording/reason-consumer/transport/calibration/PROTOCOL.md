## Decisions and comparators

A controller is readable only when read access is supplied and its registers have valid encodings. It is qualified only when also installed, recoded, and `last == 1`. An inactive controller may retain evidence; activity is an execution condition, so it is not silently required for reading retained registers. Scope/current-publication checks must use the independently bound destination rather than accepting a token's self-description.

For a current command and qualified controller in the admitted scope, equal commands produce `corroborated`; unequal commands produce `disagreement`; unavailable, unqualified, stale, or mismatched inputs produce `unknown`. Conditional corroboration means the conclusion follows **if** qualified-register soundness, stable target meaning, honest inspection, and the scope relation hold. Agreement does not prove those premises.

Disagreement requests review. It neither determines which channel is false nor permanently vetoes a source. Correct newly warranted evidence can conflict with a stale qualified controller. The separate direct-controller comparator emits the qualified candidate without reason replay; it does not supply the support objective, authority, recipient routing or physical affordability. A conventional equality/table comparator must match every abstract decision exactly. No algorithmic or performance advantage is claimed.

It does not alter a registered token under its old content-derived identity or claim that the earlier registry would accept such an alteration.
