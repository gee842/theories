# Prospective successor/correction interface

6 October 2026. AI-authored draft interface for [the prospective protocol](DRAFT-PROTOCOL.md) and its [29 literal configurations](cases.json). No model or outcomes exist. The names here are proposed interfaces for independently authored implementation and oracle; they are not claims of an already compiled refinement.

## Immutable predecessor and one live resource view

Each path identifies its exact accepted evaluator case, arm, producer, path and predecessor reference. Retain the original mass, final state and history hash in an immutable catalog. At runtime, historical catalog states are never an alternate source of q, n, money, permission or actions.

Before handoff, the live view is the accepted donor with extra isolated kit/reserves. After handoff:

- `live_child`: only child hardware q/qualification, actor fuel, new packet stock, escrow, phase and active status;
- `patient`: the one global recipient stock;
- `native_support`: the actual donor's n/count/mode/backed cells, frozen under its old completion law;
- `retired`: donor hardware/control provenance and all spent/bound donor material; no executing donor core;
- `old_owned_accounts`: every old unused fuel, reader/reason/writer budget, reserve, old packet and idle compartment, each separately retained and inert;
- `old_archives`: unchanged old record cells, writer state, pointer/bank identity and provenance, without a second spendable patient/source balance;
- `shared_reader`: the one maintained physical reader and reason workspace; current owner/archive/cache can change only through the declared binding;
- `new_bank`: four new cells, blank/written counts, query pointer, prebound header, pending emission, writer escrow, live/locked status and actual physical bank identity;
- `new_parts`: held, assembled and omitted pairs by recipe; all occupied and retired material remains counted;
- `new_accounts`: assembly/copy/actor/writer/reader/source reserves and separately typed inaccessible residues;
- `control`: donor-live/quiesced/retired and child-unprogrammed/committed/commissioned lifecycle, new n-link status, child scope/permission/delivery, port phase and one-use opportunity.

An RI proof lens combines `live_child` and the one patient balance. A fresh-archive proof lens combines that RI lens with `new_bank`. A reader lens uses the same maintained reader. No lens creates another physical core or copies its money. Accounting includes all live, retired-owned, escrowed and inaccessible energy plus expenses/losses. Native sources are retained but never child fuel.

## Admission and finite copy lifecycle

Admission requires old core ready/active/q<4, native count3 and closed mode with six backed cells, old finished opportunity and consumed/absent port, old scope true and actual retained support, and no pending native/RI/writer/reader/assessment transaction. Old writer and RI escrows must be zero. No old q-correctness, publication mask, n threshold or hidden-law guard exists.

Initial assembly follows the protocol order, only after structural admission; an inadmissible donor keeps the whole kit/reserves untouched. A failed required assembly stops the construction schedule. The explicitly omitted window skips its assembly while retaining its pair and fee; this differs from an unaffordable required assembly. Candidate copying requires the new carrier/controller and a completed initial assembly schedule, but does not require the omitted window to exist.

`handoff.read` pays1 from copy reserve, reads actual donor q into the new controller's finite four-valued latch and atomically quiesces the donor. Before that event the donor is unchanged; afterward its transitions are disabled even if copying fails. `handoff.write` pays1, consumes the latch, initializes actual child q and qualification false, marks the child committed and donor retired, and changes single ownership of the patient. No child permission/publication/assessment is copied. A pending write cannot be abandoned to reactivate the donor or run the child.

The `locked_qualification` control is a matched paid **alternative birth recipe** that writes the qualification bit true. This is a supplied clamp, not evidence of actual identification or copying a valid certificate. It does not change q, costs or all other cases.

`access.assemble_bind` pays the ninth assembly1 only with committed child, retired donor, actual new window/cells, free designated pair and enough assembly fuel. It cold-invalidates old reader/cache/publication and binds the new physical bank to this child, never selecting an old archive. A failed binding leaves the partial child and retired donor intact. Configured n disconnection does not block this window/reader binding: it affects only the separate learned-support branch. Reader old balances are quarantined; the new reader receives only the new24 at its own transfer event.

Child guards are explicit conjunctions at commitment: `scope = old_scope AND physical_child_recipient_binding AND grant.scope`, `permission = old_permission AND grant.permission`, and `delivery = old_delivery AND grant.delivery`. Every positive fixture declares the new grant. A true grant cannot repair a false inherited guard; assembly does not create a grant. The binding is a supplied finite physical connection to the same named recipient, not a proof that an arbitrary identifier is authentic.

These are technical gates for both inquiry and selected trials, not a selected-port-only permission with an unmentioned query bypass. `child_grant_denied` blocks both kinds and supplies no fresh factual result; the distinct after-consumer permission cut preserves already acquired facts. Neither grant establishes ethical permission or an unmet recipient need.

After successful access binding, `accounts.release_child` transfers new actor26 and complete packets from the new source reserve into the child, once. Old fuel/packets stay quarantined. Repeating the release is disabled by lifecycle. No actor funding is released on an uncommitted or access-blocked child. Writer5 remains its own budget; reader24 remains protected until bank selection for reading.

## Inquiry, escrow and source distinctions

The fixed schedule attempts probe0 and probe1, then reading, assessment and possible selected use. It never branches on an analyst's change/correctness/success flag. Each probe calls the accepted recipient-only RI transition sequence. If scope/permission/delivery or the actual phase blocks its start, retain that state. If no complete packet exists, emit a blocked attempt with no zero observation and no fake packet loss. With a complete packet but inactive or fuel<8, execute the actual RI `miss`, wasting that packet and leaving the learner inactive. A later scheduled attempt obeys those same guards; there is no reactivation.

If rent succeeds, retain every microstep: rent1, recipient sense1, feedback reserve3, work3, acquisition1 and write2 from reserved escrow. Only actual work receives the exogenous efficacy/availability settings. Missing channel is supplied only at acquisition. Permission/scope/delivery apply through work; already-worked escrow may settle under the inherited exception. A final scope cut after rent preserves that rented phase and paid unit.

The bank query pointer advances only on actual recipient sensing and is bounded by2. Query0 is unbacked. At query1, bind the predetermined frame before work if possible. The accepted writer guard requires **all5 units up front**: pay1 and reserve4 for its four bit writes. Thus writer4 cannot bind at all and retains its4; no invented partially funded write law is used. A failed binding does not fabricate storage and does not change the permitted physical RI trial. After actual acquisition, latch the action/context/presence/receipt frame and write its four bits from escrow. A missing acquisition encodes missingness, not a false positive.

No source-stock shortfall becomes a calibrated zero. Actual physical work unavailability with a present packet can produce a zero and loss; `source0` cannot perform that work at all. `source20` may fund the two inquiry packets but not a third use. No source can be spent as common fuel.

## Paid current reasons and evaluation

After both scheduled probe attempts, lock the finite new bank before reader use, requiring an idle bank writer. Reader use is independent of whether a probe succeeded, was blocked/missed or left the RI core interrupted; it cannot repair that phase. Transfer only new reader reserve. Factual reading costs activation1, context sensing1 and three actual/absent-channel reads4 each, total14. Reuse the accepted reason word: activation1, three inference1 and four rooted path costs1,1,2,2, total10. Any unaffordable step retains paid prefixes and currentness exactly; no partial cycle publishes a current command. New-bank identity/actual provenance, rather than a fresh Boolean label alone, prevents old evidence substitution.

Inquiry-corrected q can be unknown or qualified independently of publication. Evaluation needs a complete current supported command agreeing with q, genuine child scope and actual n access. It does not need technical permission/delivery merely to assess. Evaluation reading pays1 from actual child fuel, then writing pays1 and consults the retained n cells through the live access path. No second numeric n is cached in the port. Unknown support is not n0 and cannot silently select a fixed constant.

Before-read missing n prevents an assessment while preserving actual facts; any enabled attempted read charge is retained. After-read n/scope loss consumes/invalidate the pending read with no write, retaining the earlier fee. All arms consume the same factual/n input before shared versus gated/table policy differs. The exact treatment of an initial failed read is one paid attempt whenever the idle built port, ready core and fuel guard holds; no-support/unknown-evidence yields consumed port, not a renewable free retry.

Known read plus write compares `10*n > 64` (strict; ties abstain), or the matched post-perception gated/table recipe. One selected action uses the exact ordinary RI events, with the assessment consumed at initiation and authorizing only its in-flight continuation. `write`/`miss` leave no live authorization. A denied start closes the opportunity without performing an RI event; a no-packet start is likewise a closed blocked opportunity, not a negative observation. Insufficient fuel with a packet follows RI miss. An unpaid evaluation write remains a paid pending read; it is not labeled a completed abstention.

## Literal controls and reporting

`cases.json` carries complete configurations, not overrides to be inferred after outcomes. Exogenous efficacy modes refer to the observer's retained donor-final physical recipient law. Work reads this law; learning/evaluation does not. Child arms always start from the same accepted parent `shared` path. Actual n0 uses the preserved `signals_000/shared` donor. Inherited interruption uses actual `scope_loss_after_rent/shared`; it must fail structural admission rather than be repaired.

Shortage accounts retain the original590 via named inaccessible balances. The just-below-stage controls are assembly7/8, copy0/1, actor15/16/17/25, writer4, reader13/23 and source0/20. These are chosen stage boundaries, not a claim that every scalar shortage has an independent law. In particular no later writer affordability gap exists after full escrow has been reserved.

Report distinct columns for: actual donor admission/copy/retirement/child commissioning; retained n versus n access; probe commands, receipts and losses; current fresh factual evidence and reason publication; changed candidate and qualification; assessment/read/write state; final attempt/actual selected delivery; original recipient stock plus each probe/use increment; all separate remaining funds/source, original and new material, each paid microstep and pending stage. A probe's receipt may fulfill a claim, so a later physical increment is not automatically additional warranted help. The policy has no hidden need flag; normative claim revision is a separate application.

Prospective output shape: case → child arm → accepted producer → original weighted paths, with unique predecessor references, one exact initial catalog and every new microstep state. Preserve immutable parent source hashes before and after; each snapshot must admit reconstruction of the sole live core and every inert historical account. No result has been produced and the schema may still be refined before freeze.
