# Preserve meaning when a reason becomes a command request

6 October 2026. AI-authored integration-only experiment. The named connection is **actual recipient publication → an instrumental proposition in its declared scope → a request about that same patient, purpose and command**. [The prospective protocol](PROTOCOL.md) fixes the obligation. This package supplies an abstract semantic contract, not physical output hardware, ethical grounding or an executed intervention.

## Why a typed interface is needed

The parent's root means a supplied objective `G` to support one recipient. Its other two nodes mean `G` together with compatibility of command zero or command one with that recipient's response law. In the separate protection branch those positions denote two different patients. Equal mask shape does not preserve the patient or the proposition. A fixed permutation from command bits to patient bits changes the designated patient when the same recipient's orientation changes. A valid many-to-one patient interpretation must preserve the command separately.

Here every token carries, or receives from the trusted enclosing interpretation, the patient, root, proposition kind, causal-law identity, controller identity, deliberator role, process identity, command, context and publication provenance. These labels are **supplied bindings**. Their presence does not prove calibration, legitimate authority or moral significance, nor must every physical implementation store every field in each record.

## What this implementation consumes

[model.py](model.py) projects actual saved parent histories. The frozen [evidence manifest](evidence/manifest.json) records source hashes and the transformation. Exact parent and archive result bytes are preserved in deterministic gzip files; decompression must reproduce their recorded SHA-256 values. A small parent model/protocol and semantic-source snapshot are retained for interpretation. The projection keeps every input row, its original probability, precursor reference, complete final operating snapshot, all reached publication events, controller metadata and finite final stocks.

This is a snapshot of **provisional parent results**. It does not inherit acceptance merely because a result file exists. Capture checked the parent's declared source dependencies before and after reading. Reproduction of this package uses the frozen bytes, so later edits in a concurrent parent study do not silently change this evidence. Neither the snapshot nor its projection counts as an independent observation. The full ancestral physical process is not rerun or formally refined here.

`registry_from` creates a registry of reached uniquely supported command publications. A publication needs completed inference and path phases, current completed factual cache, matching context and exactly one nonroot command. Unknown, conflicting, root-only, partial and invalidated endpoints supply no current command token. The final snapshot identifies the current publication; an earlier publication in the same lineage is not current merely because its Boolean context tag matches. Event references and hashes are finite audit metadata, not a newly constructed free physical epoch register.

The registry implements the assumption that the enclosing execution and its source records are trusted. It can reject an unregistered identifier or altered token relative to that registry. A copied registered token remains the same token. This is not authentication from self-attested labels, a cryptographic implementation, or a detector for a consistently miscalibrated source.

## Separate decisions and their meanings

The pure `evaluate` function returns these fields:

| Field | Contract meaning |
|---|---|
| `supported_source_conditional` | The token matches a reached current registry entry. Its epistemic interpretation still assumes faithful evidence, calibration, the supplied root and relevance law. Destination policy or control loss does not erase this status. |
| `transferable_reason` | The patient, root, kind, law, controller, command, context and current publication agree with the request; the destination's independently bound current lineage/publication agrees; and an explicit nonempty supplied policy admits the source-to-destination role pair. |
| `authorized_request` | Transfer holds and the selected policy route allows it: enforced use requires the supplied authority flag; voluntary use requires separately supplied consent. These are modeled permissions, not a proof of rightful authority. |
| `local_prerequisites_met` | Existing exposure prerequisites hold: installed active controller, delivery, actor reserve at least eight and source packet at least ten. These are necessary local conditions, not a proved sufficient actuator/binding interface. |
| `request_eligible` | The request is authorized and the listed local prerequisites hold. No claim is made that the missing paid binding/write mechanism has thereby been constructed. |
| `executed` | Always false: this package executes no physical request. |
| `protection_established` | Always false: receipt compatibility has no supplied refinement to harm prevention here. |

The eight-unit prefix comes from the existing recipient exposure: rent one, target sensing one, reserved feedback three and work three. Actual acquisition and update consume the reserved three later. This adapter neither spends those units nor claims its semantic operation is physically free. Stock fields before and after are identical inherited metadata. The current primary two-cycle endpoint retains actor four, recipient twenty, reader zero and source zero. The recipient is never charged to make the test pass.

Process identity can change within an admitted role. A separately labeled delegated-role policy illustrates conditional transport beyond that identity, with its justification supplied rather than inferred from copying. An unrelated deliberator is rejected by the default policy. No new patient or harm-prevention proposition is inferred from a compatible command.

The enclosing setup assigns those roles and supplies the policy. A requester cannot establish its authority merely by asserting a role string; checking an untrusted requester's identity or delegation is outside this package. A nonempty justification label is a declared premise, not a validated normative argument. Root-only output means the current evidence supplies no unique compatible command; it does not remove the recipient's standing or negate the supplied root.

Root review found and repaired a cross-history substitution gap in the first adapter: a token and matching request from a different registered live row could be paired with this row's stocks. The destination capability state now independently binds its lineage and current publication. A cross-live-source control preserves the other token's conditional source status while rejecting dispatch into this row. It does not derive the destination identity from the incoming token.

## Positive coverage and adversarial cases

The main contract admits every current uniquely supported source command in its declared same scope. This positive coverage excludes an always-refuse implementation. Both command orientations occur. The tested changes include same-role succession, a declared delegated role, patient/root/kind/law/controller/command changes, an unauthorized role, missing transport ground, changed context, stale request publication, old reached publication, altered or invented source, delivery loss, enforcement loss and voluntary action without enforcement.

The revised implementation run processes **666 saved rows**, **246 reached command receipts**, **102 current command receipts** and **14,472 scenario evaluations**. The first run had 12,474 evaluations before the cross-history and independently changed destination-generation/lineage controls were added; its conceptual omission and repair are retained above. These are finite contract checks, not independent physical trials. For the primary variable producer, six of fourteen rows carry a current uniquely supported command, totaling probability **3/8**; each command has mass **3/16**. The remaining mass has no current uniquely supported command. Same-scope, same-role succession and the declared role transport all admit the supported mass. Patient transplant, wrong objective and old primary-cycle publications admit none.

Enforcement loss preserves the source reason and semantic recommendation while preventing the enforced permission. The separately consented voluntary route remains permitted. Actual source stocks are zero, so the local action prerequisites and executed-action counts remain zero. Inventing additional provision to obtain a favorable action result would change this study.

Consistently corrupted source tags are a decisive limitation: trustworthy preservation of those bytes is compatible with a false instrumental conclusion when the inherited calibration/integrity premise fails. This contract must not claim to detect that fault. The independent check also compares a conventional typed dispatcher and the naive patient-mask mapping; exact agreement with the conventional dispatcher establishes finite equivalence, not performance superiority.

## Reproduction and evidence scopes

Run from this directory:

```sh
python3 model.py
```

The one-time `python3 model.py --capture` creates the frozen input evidence from live parent files. It is not needed to reproduce the recorded run and must not be used to overwrite this snapshot merely because a parent changes. [results.json](results.json) holds endpoint decisions and receipt counts. The independent checker and [formal semantic contract](formal/SemanticAction.lean) have separate evidential scopes; the Lean contract is not a proof that this Python implementation or a future actuator refines it.

The next physical join must construct and pay for the actual binding/output route, show that the retained controller executes the commanded action under a sound causal law, and retain the same patient, purpose, resources and context. Ethical justification of `G`, applicability across deliberators, legitimate authority, recipient welfare and response to competing claims remain distinct obligations within the full alignment goal.
