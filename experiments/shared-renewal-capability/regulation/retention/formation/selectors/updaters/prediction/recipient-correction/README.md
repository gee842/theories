# Recipient outcomes and context-preserving correction

A conditional supporting interface for the parallel concern development. Read the [canonical account](../../../../../../../../../theories/becoming/chapters/RECIPIENT-CORRECTION.md), [protocol](PROTOCOL.md), [mathematics](../../../../../../../../../_process/research/2026-10-05-support-and-shared-generativity/completion/RECIPIENT-CORRECTION-MATH.md) and [review](../../../../../../../../../_process/research/2026-10-05-support-and-shared-generativity/completion/RECIPIENT-CORRECTION-REVIEW.md).

`model.py` composes the actual coupling preparation/eight-exposure prefix with four paid recipient/actor opportunities. It retains original twelve-packet stocks and all failure histories. `fixtures.json` stores the inherited distribution and ledgers; `results.json` stores exact full endpoint distributions for 8 fixtures × 3 upstream producers × 7 downstream arms. `check.py` checks replay, countercases and 102 affordability fixtures. `independent_check.py` independently calculates suffix transitions and aggregate distributions. [Formal proofs](formal/README.md) cover the finite information/payment interface, not the whole Python program.

Run from this directory:

```sh
python3 model.py
python3 check.py
python3 independent_check.py
python3 formal/check.py
```

Regenerate only when a substantive dependency changes. Every run pins current sources and rejects changes during execution. The predecessor's mechanisms and their earlier independent checks retain their own scope; the independent suffix check does not re-prove their origin.

An exact conventional indexed table matches; private-only and frozen indexed controls end with the same actor resources but no recipient delivery. Thus improved help does not imply a private selection advantage. Consistent target renaming is harmless; aliasing is not. Original reserve 12, missing recipient evidence and expensive writing retain different failure mechanisms.

The new paid stabilization/addressing/sensor recipes remain supplied. This is a sibling of `../coupling/concern/`, not a concatenation of its endpoint. The recipient is a separate resource account here; its own operational-use process, normative standing and evidence-channel selection are outside this suffix.
