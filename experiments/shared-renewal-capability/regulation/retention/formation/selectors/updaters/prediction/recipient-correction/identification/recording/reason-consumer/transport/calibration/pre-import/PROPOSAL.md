## Charged schedule and one-shot provenance

After the existing paid source read and before the first import:

1. **Paid candidate read, module cost1.** A formed module with unused origin permission reads the existing recipient component of `q`. Store that bit and the current binding/epoch in its own latch. Runtime does not inspect the observer law, successful-history metric or old event log.
2. **Paid qualification read, module cost1.** Read `last` into the other latch, subject to the same acquisition-origin and binding epoch. Missing/damaged access, lack of installation/recoding or an unqualified record produces `unknown`, retaining paid partial work.
3. **Paid comparison, module cost1.** Compare only the two paid latches and the paid source-command latch. If qualified and equal, issue a single-use import permit; otherwise report disagreement/unknown. No free live `q`/`last` reread is allowed.
4. **Consume before import.** Before any actual `import_command` attempt, invalidate acquisition-origin permission and consume the comparison permit. This stays consumed even if import is unaffordable or interrupted. The guard is part of the supplied new event interface, not an inferential claim from `last=1`. Subsequent trial feedback and later reason replay cannot rearm it.

The two reads cannot silently combine an old bit with a newly qualified flag. The new recipe provides an exclusive read interval and a causal invalidation hook: any intervening controller write, context/generation change, publication replacement or destination replacement invalidates partial latches and any permit. Its functional reliability is an explicit premise, tested by visible interruption controls. It requires no extra free read of the register value. External faults bypassing this interlock remain failures rather than being “detected” from an analyst's case name.

The wrapper should define actual events `read_anchor_candidate`, `read_anchor_flag`, `compare_anchor`, `consume_origin_before_import`, and `invalidate_anchor`. A control that imports early must execute the actual parent import while consuming origin permission; a later inspection must remain unavailable. The deliberately naive post-import comparator is a separate ablation demonstrating copied-evidence failure, not the production transition.

Pre-import approval does not close the approval-to-work gap. Preserve the parent's inverted-import adverse case and any explicitly declared post-approval actuator fault. Useful-receipt theorems require faithful import/actuation, or an additional separately paid verification route not supplied here. The formal parent's `Authorized` proposition involving registers must not become an unpaid executable live-register check.
