## The constructive connection

[SemanticCalibration.lean](SemanticCalibration.lean) imports the already checked positive-receipt updater. `acquire` feeds its actual `feedback` function an actor/recipient observation, using the existing causal receipt law when a channel is available and `none` otherwise. `replay` folds this same updater over a finite sequence. Starting with the qualification flag false, every replay preserves the implication **qualified → retained recipient command equals the fixed recipient law**. This composes the existing one-step invariant; it does not define qualification as truth or insert observer correctness into the runtime.

The fixed law, faithful observation and uncorrupted retained register are explicit premises. The stream represents already acquired observations. This replay neither produces them for free nor proves that arbitrary event words are physically reachable or affordable. Parent material/paid-event accounting and the independent frozen Python-history audit supply separate evidence about those interfaces.

`corroborate` takes a visible command, a retained register and a readiness Boolean. Readiness aggregates the executable inspection's explicit currentness, readability, scope, installed-state and recoding guards; the qualification flag is tested separately. It returns the command only when it agrees with the qualified retained recipient candidate. It receives no target-law argument. Its exact output characterization supports both nonvacuity and rejection: with a sound current qualified anchor, every true command corroborates and every wrong one fails to corroborate. `replay_corroboration_is_compatible` derives compatibility from the actual updater replay, rather than merely positing an unexplained sound anchor.

`grounded_corroboration_is_compatible` separately exposes the assumption needed when old and current laws are represented separately: the acquired anchor's law must still apply. A metadata scope match alone does not prove that condition. Compatibility here means the modeled receipt equals opportunity. The result says nothing about evaluative benefit, justified objectives, authority, paid delivery or conflicting claims.

## Failure boundaries

- **Disagreement does not adjudicate which side is wrong.** `disagreement_excludes_joint_current_soundness` rules out the conjunction of sound old qualification, unchanged law and a true new claim. At least one has failed; the proof does not select one. Correct new evidence can disagree with an obsolete retained controller.
- **Importing the claim destroys an independent check.** `self_import_guarantees_agreement_without_calibration` uses the actual recipient-cell write operation, preserves the existing actor cell through that operation and sets the flag true. The imported command then corroborates for every Boolean value, including under an incompatible law. Compare before import or preserve a separately grounded acquired record. Arbitrary `last=true` is not the provenance supplied by positive-receipt acquisition.
- **Agreement can have a common cause.** The two finite worlds share the complete declared visible state, including `q`, qualification, command and readiness; only their physical law differs. One world's agreement is wrong. No decoder of that state can identify both laws. This countermodel does not hide a distinct available controller record to manufacture ambiguity.
- **Stale qualification can accept error and decline truth.** A previously correct qualified record remains unchanged after an unsignaled law reversal. Its old claim corroborates but has no receipt; the newly correct claim does not corroborate. Accordingly the interface outputs corroboration/disagreement/unknown, not an unconditional action veto.

The repository's more general `ControllerRevision.same_feedback_excludes_incompatible_futures` already establishes the full-history information limit for equal initial memories and complete accessible feedback. The local two-world theorem is its finite calibration illustration, not a new universal impossibility claim. Supplying a genuinely informative probe or preserving a sound original register can distinguish worlds excluded by the countermodel.

## Executable correspondence and its limits

The adjacent [inspection model](../model.py) additionally checks integer encoding, publication generation, independently supplied destination binding and unavailable-read cases. Its `q >> 1` agrees with the imported finite recipient candidate for valid encodings 0–3; its `last==1` corresponds to the Boolean qualification flag. The independent checker reconstructs these states from exact frozen histories. This source-level correspondence is not a formal proof that Python implements Lean.

An inactive controller can retain readable evidence; the executable inspection deliberately does not confuse action activity with record accessibility. The proposed reader is abstract and expressly unimplemented. Its stock snapshot is unchanged. No field in this formalization supplies the missing physical read, binding or execution route.
