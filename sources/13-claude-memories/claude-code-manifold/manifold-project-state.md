Manifold is Ren's personal web environment product, split out of deepseek-harness (dsh) on 2026-08-30/31. dsh stays the upstream agent harness, mounted as a SHA-pinned read-only submodule at `dsh/` whose packages resolve as pnpm workspace members; one Cordis instance (dsh/vendor — the project's own maintained fork, no upstream cordis-js tracking) serves both trees. The governing plan is `dsh/.agents/notes/implemented/architecture/2026-08-30-manifold-product-split.md`; AGENTS.md states the binding rules (submodule read-only, dependency direction manifold→dsh only, `@manifold/<x>` naming, no ctx/event/slot/SessionEventMap renames, English-only docs).

Layout: 93 owned `@manifold/<x>` packages at `packages/<group>/<pkg>` — the identity plane (util/home-paths, boot/{app-boot,cmdline}, the six user-data providers + bundle/local-machine, owning `$MANIFOLD_HOME` and the `MANIFOLD_` tool-shell namespace), the domain families (space/, note/, plugin-runtime/, automation/), the browser stack (client/* ~45, host/* 8, api/remotes, two extensions, session-log-export, client-test-runtime), and the seven product bundles. `apps/manifold` (bin `manifold`) and `apps/web` (frontend). The web profile composes dsh runtime-core + dsh agent-standard + the seven @manifold bundles. Gates: `pnpm run gates` = typecheck, test, build, snapshot, cordis-config, paths-coverage, doc, rescope, no-session-events, submodule-clean, dsh-resolutions, web.
