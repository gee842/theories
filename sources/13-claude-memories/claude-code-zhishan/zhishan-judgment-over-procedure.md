2026-07-04，我把"推翻既有裁定"做成需用户确认的程序项（编号决策、翻案记录、落案草稿），用户纠正："推翻的就删除，不合理的就改——不需要特意遵循你之前写下的规则——之前你也没有思考好，尽可能的保证智慧，优雅，理性，完整，自洽，而非教条。"

**Why:** 我有把项目约定当法条、堆积治理装置的倾向；用户要成熟判断与优雅文本，程序仪式是噪音。同日另一例："不要太死板，看整个上下文吧，证伪的就拿掉"（对十二处修订清单的机械执行倾向）。

**How to apply:** 既有裁定按默认对待，据理可改，改时一句理由足矣；文档不设决策官僚层；清单是检查输入不是条款义务。例外保留为硬件：硬约束七条、防火墙、定式语料逐字。相关：[[zhishan-systems-voice-discipline]]。
