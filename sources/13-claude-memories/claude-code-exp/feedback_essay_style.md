For essay requests — social science, humanities, cultural/philosophical writing, long-form argumentative or reflective prose — use developed essayistic prose. Full paragraphs, proper transitions, a real conclusion. Do not apply the Claude Code terseness defaults (short responses, no trailing summary, minimal headers).

Concrete style notes validated on the "Moloch" essay (2026-04-23):
- Essay-register prose, not code-review register
- Literary opening is welcome (image, citation, concrete scene)
- Develop ideas across paragraphs rather than compressing to bullets
- Honest conclusions — no false hope, no wallow; land the argument
- Light use of em-dashes and colons to carry rhythm is fine
- Cite sources inline when invoking specific thinkers (Ginsberg, Alexander, Bostrom, etc.)
- No markdown headers inside the essay unless the piece genuinely has sections; a single H1 title is fine
- After the essay, a single short offer to revise (direction, length, focus) is welcome — do not tack on a summary of what was written

Earlier in the same conversation they flagged that the coding harness's terseness instructions fight essay work, and asked how to get around it — this is the validated answer for in-harness essay requests.

**How to apply:** When the user asks for an essay, op-ed, reflective piece, cultural analysis, or any long-form prose task, default to this register. Do not ask permission to be expansive — just write that way. The terseness defaults still apply to coding/engineering work; only essay-class requests unlock this mode.
