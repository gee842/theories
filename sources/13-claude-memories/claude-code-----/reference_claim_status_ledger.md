**Status vocabulary** (use these terms when describing what's in code):
- **closed** — non-placeholder Lean theorem/definition with claim content
- **scoped** — real theorem, restricted by base / carrier level / supplied structure fields
- **schema** — Lean object fixes claim shape; fields/hypotheses left to instantiation
- **external route** — standard math suggests reduction; bridge theorem not stated/proved here
- **sketch** — plausible direction named; no theorem-grade reduction
- **placeholder** — `True`, `coherent := True`, vacuous at load-bearing point
- **open** — obligation stated, no proof

**How to apply**:
- When asked about status of any T_GUT / R-Family / FullGUT / Wen / Heisenberg-Weyl headline, **grep the ledger first** before quoting README or memory.
- When writing new doc that describes status, use the ledger's vocabulary — don't invent terms like "done" / "stable" without anchoring to a ledger row.
- When editing claim-bearing docs, the user wants aspirational claims **preserved verbatim**; only annotate status by linking to a ledger row.
