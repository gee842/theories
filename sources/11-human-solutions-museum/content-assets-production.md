# 内容资产制作说明

## 当前结论

内容资产第一版已经可以支撑静态交互原型，但不等于正式公开发布稿。

当前核心文件是：

- `data/museum-content.json`
- `schemas/museum-content.schema.json`
- `scripts/validate-content.mjs`

它不是百科词条库，而是前端可直接消费的“问题解决档案”数据源。每个展品围绕真实问题、常见误解、关键洞察、机制、副作用和可迁移方法组织。

当前状态口径：

- `contentStatus.prototypeReady: true` 表示足够支撑产品原型；
- `contentStatus.publicationReady: false` 表示还不能作为正式公开事实档案发布；
- 没有来源、审核和视觉授权的内容，只能按 prototype copy 使用。

## 内容资产分层

### 1. 产品结构层

这一层定义网站如何组织内容：

- 品牌名称、副标题、项目定位；
- 首页问题入口；
- 展厅；
- 展品；
- 方法库；
- 结构相似跳转；
- 入馆申请表；
- 活博物馆机制。
- 来源、审核、敏感性、视觉资产和发布门槛。

这些内容已经进入 `data/museum-content.json`。

### 2. 种子展品层

第一版包含 10 个种子展品：

| 展品 | 当前深度 | 用途 |
| --- | --- | --- |
| 文字 | seed | 卡片、短详情页、方法跳转 |
| 纸 | seed | 卡片、短详情页、方法跳转 |
| 印刷术 | seed | 卡片、短详情页、方法跳转 |
| 避孕套 | anchor | 完整样例、气质锚点、长详情页 |
| 疫苗 | seed | 卡片、短详情页、方法跳转 |
| 图书馆 | seed | 卡片、短详情页、方法跳转 |
| 眼镜 | seed | 卡片、短详情页、方法跳转 |
| 科学方法 | seed | 卡片、短详情页、方法跳转 |
| 无障碍设计 | seed | 卡片、短详情页、方法跳转 |
| 开源协作 | seed | 卡片、短详情页、方法跳转 |

`anchor` 表示可以作为第一版重点展品；`seed` 表示足够进入 MVP，但后续还可以继续扩写、补充史料和案例。

当前 10 个展品适合验证产品结构，但不是长期馆藏的平衡状态。后续需要补充法律、合同、货币、医院、心理治疗、学校、工会、人权、公共卫生制度等制度性案例，避免项目停留在知识传播、身体工具和数字协作几类漂亮例子上。

### 3. 方法库层

方法库目前不是从展品标题机械抽出来的关键词，而是可被用户“借走”的行动原则。

当前方法包括：

- 把记忆移出身体；
- 让知识变轻、变便宜、变可携带；
- 降低复制成本；
- 把传播变成标准流程；
- 给私人场景一个低成本接口；
- 在危机前训练系统；
- 用小工具延长人的能力；
- 把私人储藏变成公共空间；
- 用过程替代权威；
- 让工作可检查、可复现、可修正；
- 用共享协议组织陌生人；
- 降低发声门槛；
- 把个体缺陷重写为环境设计问题；
- 把私人风险接入公共系统。

前端可以把这些作为“文明工具箱”的收藏对象。

## 数据结构说明

### 顶层字段

- `brand`：网站名称、定位、首页主问题；
- `entryPrompts`：首页问题入口；
- `galleries`：问题展厅；
- `methods`：可迁移方法；
- `exhibits`：展品档案；
- `nominationForm`：入馆申请表；
- `livingMuseum`：开放提名和策展机制；
- `publicationPolicy`：公开发布门槛；
- `sources`：来源表；
- `contentStatus`：内容可用状态和发布前提醒。

### 展品字段

每个展品应至少包含：

- `id`：稳定标识，用于路由和跳转；
- `slug`：URL 友好的路由名；
- `routePath`：当前静态路由；
- `order`：展示顺序；
- `depth`：`anchor` 或 `seed`；
- `primaryGalleryId`：主要归属展厅；
- `galleryAppearances`：它出现在哪些问题展厅中；
- `name`：展品名；
- `title`：带解释力的标题；
- `oneLine`：卡片摘要；
- `coreProblem`：它面对的真实问题；
- `commonMisreadings`：过去或常见的误解；
- `keyInsight`：关键洞察；
- `mechanism`：它如何发挥作用；
- `diffusion`：它如何扩散；
- `whatItSolved`：它解决了什么；
- `newProblems`：它制造或暴露的新问题；
- `borrowableMethodIds`：关联的方法；
- `methodTakeaway`：用户可以带走的方法句；
- `sections`：详情页统一渲染段落；
- `similarStructures`：结构相似展品跳转；
- `ui`：展陈编号、标签等前端展示字段。
- `publicationStatus`：内容发布状态；
- `publicationReady`：是否可以作为公开事实档案发布；
- `reviewStatus`：文案、事实、敏感性审核状态；
- `evidence`：来源 ID、证据等级和引用状态；
- `timeline`：关键历史节点；
- `assets`：主视觉和机制图；
- `sensitivity`：敏感性等级、类别和措辞提醒；
- `search`：别名、关键词、筛选和反向搜索字段。

`anchor` 和 `seed` 都使用 `sections`，区别只是内容深度。不要再让前端为长详情和短详情维护两套渲染结构。

### 方法字段

每个方法除标题、原则和适用场景外，还预留：

- `steps`：后续扩写成可执行步骤；
- `antiPatterns`：常见误用；
- `notApplicableWhen`：不适用边界；
- `failureSignals`：失败信号。

这些字段可以先为空数组，但不要从 schema 中删除。它们是避免方法库口号化的长期接口。

## 第一版前端怎么使用

建议第一版直接读取 `data/museum-content.json`：

1. 首页渲染 `brand` 和 `entryPrompts`；
2. 问题星图渲染 `galleries`；
3. 展品浏览页渲染 `exhibits`；
4. 展品详情页按 `slug` 或 `routePath` 定位展品，按 `sections` 渲染；
5. 方法库渲染 `methods`；
6. 工具箱收藏 `method.id`，先用浏览器本地状态模拟；
7. 入馆申请页渲染 `nominationForm.fields`。

每次修改内容后运行：

```bash
npm run validate:content
```

校验内容包括：

- ID 唯一性；
- 展厅、展品、方法、来源引用完整性；
- 展品是否有统一详情结构；
- 结构相似跳转是否有关系类型、维度和置信度；
- 投稿表单是否保留来源、证据、争议、版权、利益关系和敏感类别字段；
- `publicationReady` 内容是否满足来源和审核门槛。

## 发布前还要补什么

当前内容适合产品原型，不等于正式公开发布的历史考据稿。

公开发布前建议补四类资产：

### 1. 来源和事实校对

每个展品补：

- 关键历史节点；
- 可靠来源；
- 争议点；
- 需要避免的过度概括；
- 可引用的延伸阅读。

来源应进入顶层 `sources` 表，展品通过 `evidence.sourceIds` 引用来源。不要把来源散落在正文里。

### 2. 视觉资产

每个展品补：

- 一张主视觉；
- 一张机制图或结构图；
- 展品编号和印章样式；
- 方法胶囊视觉样式；
- 问题星图节点样式。

视觉资产进入 `assets` 字段。正式发布前，主视觉至少需要 `src`、`alt`、`credit` 和 `license`。

### 3. 长文扩写

第一阶段只需要避孕套作为完整样例。

后续优先扩写顺序建议：

1. 印刷术；
2. 疫苗；
3. 无障碍设计；
4. 开源协作；
5. 科学方法；
6. 图书馆；
7. 文字；
8. 纸；
9. 眼镜。

优先级依据是：这些展品更能体现“问题不是单点技术，而是机制、扩散和社会结构”的项目差异。

### 4. 策展审核规则

后续需要把入馆标准写成可执行规则，例如：

- 是否回应真实问题；
- 是否改变处理问题的基本方式；
- 是否扩大表达、选择、尊严、自由、安全、协作或理解能力；
- 是否能提炼出可迁移方法；
- 是否完整呈现副作用和争议。

发布流程至少应保留以下状态：

1. `proposed`；
2. `drafted`；
3. `fact-checking`；
4. `sensitivity-review`；
5. `published`；
6. `revised`。

没有来源和审核的内容只能作为原型文案，不应以正式事实档案口吻公开。

## 内容验收标准

第一版内容资产完成的最低标准：

- 用户能看出这不是发明百科；
- 每个展品至少有问题、误解、洞察、机制、方法；
- 避孕套案例足够完整，可以作为项目气质锚点；
- 方法库不是口号，而是可迁移的行动原则；
- 展品之间有结构相似跳转；
- 入馆申请表本身能逼迫推荐者认真思考。

以上标准当前对“原型内容”已经满足；对“正式发布内容”尚未满足。

## 下一步建议

如果下一步进入网页实现，优先级是：

1. 用 `data/museum-content.json` 搭首页和问题入口；
2. 做问题星图和展厅浏览；
3. 做展品详情页，先把 `condom` 渲染成完整样例；
4. 做方法库和本地收藏；
5. 做入馆申请表；
6. 最后补视觉资产和移动端细节。

如果下一步进入内容扩写，优先级是：

1. 给避孕套补来源、时间线、限制和争议说明；
2. 给疫苗、无障碍设计、科学方法补敏感性和事实来源；
3. 给每个方法补 `steps`、`antiPatterns`、`notApplicableWhen` 和 `failureSignals`；
4. 扩展法律、合同、货币、医院、心理治疗、工会、人权等制度性展品。
