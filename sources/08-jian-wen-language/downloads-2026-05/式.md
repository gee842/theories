## 起

《理》立根基,《气》言对应。这份文档接续《气》,做一件事:把工程对应中的 commitments 提炼为形式化的 reduction system,让间的 dynamics 被严格陈述,让间的 properties 可被精确 reasoning。

形式语义不是工程实现的替代,也不是工程实现的 specification——它是 dynamics 的数学表达。它让我们能够 reason about 一个 implementation 是否 honor 间的 commitments,能够证明某些 invariant 跨 implementation 成立,能够 articulate 间的形式 character。

这份文档假设读者熟悉基本的 reduction semantics 和 process calculi(π-calculus、actor model)。但即使没有这些 background,关键概念的 motivation 都会 explicit 给出,通过类比可以 follow。

理事不二,气式不二。这份文档不是从《气》派生形式系统,这份文档是同一个 reality 在数学 register 下的 articulation。

## 一、为什么标准 calculi 不够

存在的形式系统中,几个最相关:

**π-calculus**:擅长 mobility 和 fresh names,通过 channel passing 表达通信。但 π 中的 channel 是 ontologically prior 的——name 是 first-class,actor (process) 是其上的 derived structure。这跟间的 actor-first commitment 相反。π 也没有 native location,要表达 jian 必须用 encoding,失去直接性。

**Actor model (Hewitt-Agha)**:actor-first 但通常不够 formal。Agha 的 actor calculus 给了 reduction relation 但没有 native nesting,jian 必须用 supervision tree encode。Message 是 inert data,不是 first-class occasion。

**Distributed π (Hennessy)**:加了 locations,但 locations 是 syntactic level 的 wrapper 不是 first-class entity——location 不能被 passed、被 modified、被作为 actor 处理。

**Mobile Ambients (Cardelli-Gordon)**:nested locations 是 native,但 ambient 的运算(in/out/open)是 location-mobility 而不是 actor-interaction primitives。Ambient 不发消息,ambient 是被 moved 的。

**Join calculus**:distributed-friendly 但 join pattern 跟 jian 的 emergent boundary 不直接对应。

**E / vat-based ocap**:实现层面对 capability discipline 处理得最好,但 vat 是 implementation primitive 不是 calculus level concept,formal 化时往往 fall back to π。

我们需要的形式系统:

1. **Actor as primary primitive** —— 不是 process-on-channel 而是 actor-with-mailbox。
2. **First-class jian** —— jian 是 actor,有 name、可被传递、有 reflexive capabilities。
3. **Native nesting** —— actors-in-jian 是 ontological 关系,不是 encoding。
4. **First-class events** —— 每个 occasion 有 identity,可以被 prehended。
5. **Capability as actor** —— capability 不是 separate primitive,是 forwarder-style actor。
6. **Derived predicates over configurations** —— caveat / visibility / protocol legitimacy 是 predicate 不是 primitive。
7. **Perspectival equivalence** —— observation 是 from-within,equivalence 是 relativized to observer。

这套要求没有任何现有 calculus 单独满足。下面我们设计一个,称为 **间演算**(Jian Calculus,简记 **JC**)。它选取性地借鉴上述各 calculus 的优点,同时严守理与气的 commitments。

## 二、Configurations

JC 的运行时状态称为 **configuration**(配置),用 `Σ` 表示。

### Names

```
a, b, c, ... ∈ Names      (actor names, including jian names)
e, f, g, ... ∈ EventIds   (event identifiers)
m, n, ...    ∈ MsgTags    (message tags / labels)
```

Jian names 是 Names 的 subset——所有 jian 都是 actor,所以 jian names 也是 actor names。

### Actors

```
Actor ::= a[B; σ; M; H]
```

其中:

- `a` ∈ Names 是 actor 的名字
- `B` 是 actor 的 behavior(从 message + state 到 actions 的 function)
- `σ` 是 actor 的 private state
- `M` 是 mailbox(待处理 messages 的队列)
- `H` 是 actor 的 history(已处理 events 的序列)

注意 `H` 的存在——它是 actor 的 worldline,不是 implementation cache,而是 actor's first-class history,是动静不二的形式表达(state 是 history 的 fold,history 是 first-class 的)。

### Events / Occasions

```
Event ::= ⟨e | π; ξ; ℓ⟩
```

其中:

- `e` ∈ EventIds 是 event 的唯一标识
- `π ⊆ EventIds` 是 event 的 prehension set(它 reference 的 predecessors)
- `ξ` 是 event 的 content(message body、actor action 等)
- `ℓ` ∈ Names 是 event 发生所在的 jian

每个 event 携带它自己的 prehension。这是 Whitehead actual occasion 的形式化——每个机缘 explicit 知道它 prehended 哪些前驱机缘。

### Messages

```
Msg ::= a → b: m⟨v⟩
```

In-flight message:from a, to b, tag m, payload v。注意:message **不是**与 event 分离的 entity——message 是 in-flight 状态的 message,一旦被 received,它 reify 为新的 event(有自己的 EventId 和 prehension,prehending 它的 send event 和 receiver 当时的相关 events)。

### Jian

Jian 是 actor 的 specialization,有额外的 internal structure:

```
Jian ::= j[B_j; σ_j; M_j; H_j; A_inner]
```

`A_inner` 是 jian 内部的 actor configuration——一组 actors、events、messages 以 j 为 location。这个结构 explicit 表明 jian 既是 actor(有自己的 behavior、state、mailbox、history),又是 container(有 inner configuration)。

但 inner configuration **不是** stored attribute——它是 actors-in-jian 的当下 collective state,通过 jian 的 ongoing internal activity 维持(见 §八)。在 syntax 上 explicit 写出来是为了 formal 处理 nesting,在 semantics 上必须 honor autopoietic dynamics。

### Configuration

```
Σ ::= ε                        (empty)
    | Σ ∥ Actor                 (parallel: add actor)
    | Σ ∥ Jian                  (parallel: add jian)
    | Σ ∥ Msg                   (parallel: add in-flight message)
    | Σ ∥ Event                 (parallel: add event)
    | (νa) Σ                    (name binding: a is fresh in Σ)
```

`∥` 是 commutative associative,with `ε` as unit。Configuration 是 actors / jians / events / messages 的 parallel composition。

要点:**configuration 中没有 global state component**。没有 "the system state"——只有 parallel composition of localized entities。这跟 no-god-view commitment 一致——形式系统从 syntax 层就拒绝 global state。

## 三、Reduction relation

`Σ ⟶ Σ'` 表示 configuration `Σ` reduce 为 `Σ'`。

### 基础 reductions

**(R-Recv)** Actor 接收 message:

```
a[B; σ; M; H] ∥ (b → a: m⟨v⟩)
    ⟶
a[B; σ'; M ∪ actions; H · ⟨e | π_recv; m⟨v⟩; ℓ⟩]
```

其中 `(σ', actions) = B(σ, m, v)`,`actions` 中的 spawn / send 在后续 reduction 中分别生成。`e` 是 fresh EventId,`π_recv` 包含 send event(如果 known)和 receiver 当时 history 中的相关 events。`ℓ` 是 receiver 当前所在的 jian。

注意:message 被 received 后立即 reify 为 event,加入 actor 的 history。**Message 不消失,只是从 in-flight 转为 historical occasion**。

**(R-Send)** Actor 发送 message(作为 receive 的 follow-up action):

```
a[B; σ; M_with_send_action; H · e_recv]
    ⟶
a[B; σ; M_minus_send; H · e_recv · e_send] ∥ (a → b: m⟨v⟩)
```

`e_send` 携带 prehension `{e_recv} ∪ relevant_history`,因为 send 是 receive 处理的 consequence。

**(R-Spawn-Actor)** Actor spawn 新 actor:

```
a[B; σ; M; H · e_recv]
    ⟶
a[B; σ; M; H · e_recv · e_spawn] ∥ (νb)(b[B'; σ_init; ∅; ∅])
```

`b` 是 fresh,初始 behavior `B'`、初始 state `σ_init`,空 mailbox,空 history。`e_spawn` prehending `{e_recv}`。

**(R-Spawn-Jian)** Actor spawn 新 jian:

```
a[B; σ; M; H · e_recv]
    ⟶
a[B; σ; M; H · e_recv · e_spawn_j] ∥ (νj)(j[B_j; σ_init; ∅; ∅; ε])
```

`j` 是 fresh jian,内部 configuration 初始为 empty `ε`。注意 jian spawn 时是 empty 的,但它**必须立即**开始 spawn 内部 actors——否则它没有 ongoing activity 维持它,在下个 autopoiesis check 时就会 dissolve(见 §八)。

**(R-Become)** Actor 改变 behavior:

```
a[B; σ; M; H · e]
    ⟶
a[B'; σ; M; H · e]
```

如果 `e` 的 action 包含 `become(B')`。这是 actor model 的 standard primitive,允许 actor 的 behavior 演化。

### Jian-specific reductions

**(R-Enter)** External actor 进入 jian:

```
a[B_a; σ_a; M_a; H_a] ∥ j[B_j; σ_j; M_j; H_j; A_inner]
    ⟶  if caveat_j(enter, current_Σ) = true
j[B_j; σ_j'; M_j; H_j · e_enter; A_inner ∥ a[B_a; σ_a; M_a; H_a]]
```

只在 caveat predicate(见 §七)允许时发生。`e_enter` 记录 a 进入的 occasion。注意 a 现在 nested 在 j 内部,a 之前所在的 outer configuration 不再 directly include a——a 被 moved into j's `A_inner`。

**(R-Leave)** Actor 离开 jian:

```
j[B_j; σ_j; M_j; H_j; A_inner ∥ a[B_a; σ_a; M_a; H_a]]
    ⟶
j[B_j; σ_j'; M_j; H_j · e_leave; A_inner] ∥ a[B_a; σ_a; M_a; H_a]
```

`a` 回到 outer configuration。

**(R-Cross)** External actor 给 nested actor 发 message(通过 jian boundary):

```
a[...] ∥ j[B_j; σ_j; M_j; H_j; A_inner ∥ b[...]]
    ⟶  if visible(a, b, current_Σ) = true
a[...] ∥ j[B_j; σ_j; M_j; H_j; A_inner ∥ b[...]] ∥ (a → b: m⟨v⟩)
```

只有当 a 持有 capability 使得它在 capability graph 中 reach b——这通过 visibility predicate 检查。否则 message 不被 created,a 收到 capability error。

### Locality

每个 reduction 是 **local** 的——只涉及 finitely many actors / jians / events / messages。**没有 global reduction step**。这跟 no-god-view commitment 一致——reduction 也是 perspectival 的,no observer needed to coordinate。

### Concurrency

多个 reductions 可以并行进行,只要它们 **disjoint**(涉及的 actors 不重叠)。Configuration 的 `∥` 结构使 concurrency 显式:任何不依赖的 reductions 可以 simultaneously occur。这是 reduction system 的 standard structural concurrency。

## 四、Meta-circularity:jian as actor

JC 的核心 design:**jian 是 actor**。具体地:

```
∀ j ∈ Names. j is jian ⟺ j has internal configuration A_inner
```

但 jian 仍然 **是 actor**——它有 behavior、state、mailbox、history,跟普通 actor 完全一样。区别只在于它 additionally 有 internal configuration `A_inner`。

这给了 jian 三种 interaction modes:

1. **As actor**: 接收外部 message,执行 behavior,改变 state——跟普通 actor 一样。
2. **As container**: 内部 actors 之间 interact,events 在 internal configuration 中 unfold——这些都是 jian 的 internal activity。
3. **As boundary**: external actors 通过 capability 跟 internal actors interact——通过 (R-Cross) 这类 cross-boundary reduction。

这三种 mode 都是同一个 jian-as-actor 的不同 register。Jian 的 reflexive capability 在 behavior `B_j` 中实现——它能 query 自己的 internal configuration(membership、history),能 modify(允许新 actors 进入、forcibly remove)。形式上,这通过 `B_j` 在 `A_inner` 上的访问实现——jian 作为 actor 拥有对自己 inner configuration 的 first-class access,这是反身性的具体形式。

注意:**jian 的 internal configuration 不是 stored attribute**。它是 ongoing 的——通过 internal actors 的 ongoing activity 维持。这通过 §八 的 autopoiesis 条件 enforce——`A_inner` 出现在 syntax 中是为了 formal 处理 nesting,但它在 semantics 上必须 honor autopoietic dynamics,otherwise jian dissolves。

### Recursion: jian-in-jian

Jian 可以 nested。一个 jian 的 internal configuration 可以包含其他 jian:

```
Σ_universe
  ⊃ j_organization
       ⊃ j_team
            ⊃ j_meeting
                 ⊃ j_breakout
                      ⊃ ...
```

每一层都是 jian,都是 actor,都有自己的 reflexive capability,都有自己的 autopoietic dynamics。

但**没有最外层**。任何具体 deployment 是一个 jian,但它 ontologically 嵌套在 cosmic 间中——cosmic 间不是 first-class entity in JC,它是 the ontological context that all JC reductions take place within。形式上:JC 不需要 explicit "top jian";reduction 只在某个具体 configuration 内部发生,这个 configuration 可以 unbounded nested upwards。任何 specific JC reasoning 是相对于某个 context Σ 的,这个 Σ 可以是某个外层 jian 的 internal configuration,也可以是 standalone deployment。

## 五、Prehension

每个 event 携带 prehension set `π`——它 reference 的 causal predecessors。这给了 history 一个 DAG 结构,而不是 linear timeline。

### Causal graph

定义 causal graph `G(Σ)`:

- **Vertices**: 所有 events in Σ(包括各 actors 和 jians 的 history 中的 events)
- **Edges**: `e → e'` iff `e ∈ π(e')`(e 是 e' 的 prehended predecessor)

这是一个 DAG——events 不能 prehend 自己或后代,通过 EventId 的 fresh generation 保证。

### Prehension closure

对 event `e`,定义 `π*(e)` = e 的 transitive prehension closure(所有 e 直接或间接 reference 的 events)。这是 "e 的 causal past"。

两个 events `e` 和 `e'` 是 **causally independent** iff `e ∉ π*(e')` ∧ `e' ∉ π*(e)`。Concurrent reductions 必然涉及 causally independent events。

### Linear time as projection

任何 linear time ordering(给所有 events 一个 total order)是 G(Σ) 的一个 **topological sort**——是它的 projection,不是它的 reality。不同 observers 可能选择不同 projection;**没有 canonical linearization**。

这是相对论 simultaneity relativity 的形式化对应。两个 observers 可以对 "events e and e' which happened first" 给出不同 answer,只要他们的 answers 都是 G(Σ) 的合法 topological sort。两个答案都对——绝对的 first 不存在。

### Prehension 的 information content

Prehension 不只是 causal record,它 carries information:event `e` 的 content `ξ` 可以 reference(through `π(e)`)它 prehended 的 events 的 content。这让 events 形成 informationally interconnected graph 而不是 isolated occurrences。

例如,actor 的 decision event `e_decide` 可以 prehend `{e_msg_1, e_msg_2, e_state_check}`,意味着 decision 的 content 是基于这些 prehended events 的 information 的。这给了 distributed reasoning 一个形式 ground——decision 的 justification 通过 prehension graph 可被 reconstruct,而不需要中央 audit log。

## 六、Capability as actor

JC 中,capability **不是** separate primitive,是 actor 的 specific pattern。

### Forwarder pattern

A capability that "represents authority to send to actor `b`" 是 actor `c` with behavior:

```
B_cap(σ, m, v) = (σ, [send(c, b, m, v)])
```

C 的唯一 behavior 是把 incoming message forward 给 b。任何持有 c 的 reference 的 actor 可以 message c,效果是 message b——但通过 c 中介。

### Attenuation

带 attenuation 的 capability 是 forwarder with filter:

```
B_attenuated(σ, m, v) = 
    if predicate(σ, m, v):
        (σ, [send(c, b, m, v)])
    else:
        (σ, [])  
```

如果 `predicate` 失败,message 不被 forward。这是 caveat / restriction 的具体形式——任何对 capability 的限制都是 forwarder actor 的 behavior 中的 filter logic。

### Revocation

Capability 的 revocation 是 destroy capability actor:`c` 被 terminated(或它的 behavior 改为 noop),所有 future messages to c 不被 forward。这给了 revocation 一个清晰语义——通过 actor lifecycle 实现,不需要额外 primitive。

如果 c 是 forwarder chain 中的一环(c forwards to c' forwards to b),terminating c 终止整个 chain 后续 segment 的可达性——但 c' 和 b 仍然存活,只是不再 reachable from c 的 holders。这是 revocation 的精确语义。

### Capability graph

任何 configuration `Σ` 有 **capability graph** `Cap(Σ)`:

- **Vertices**: actors in Σ
- **Edges**: `a → b` iff a 持有指向 b 的 capability(直接 reference 或 forwarder chain)

This graph evolves as capabilities are created, passed, attenuated, revoked. **Cap(Σ) 是 visibility 的基础**(见 §七)。

### Discipline: no name forging

JC 的关键 invariant:**actor a 只能 reference 它已经知道的 names**。具体地,reduction rules 不允许 actor 凭空 fabricate 一个 name。Actor a 知道 name b iff:

1. a spawn 了 b(所以 a 知道 b 的 fresh name from R-Spawn-*),或
2. a 通过 received message 收到 b 的 reference(message payload 包含 b),或
3. a 在 spawn 时被 enclosing context 给了 b 的 reference(initial knowledge)

Reduction rules 的 carefully designed structure 使得这是唯一获取 names 的方式。这是 ocap 的 fundamental commitment 在 JC 中的形式化。

## 七、Derived predicates

理与气都强调:caveat / visibility / protocol legitimacy 不是 primitive,是 derived。JC 形式化地 honor 这一点——这些是 **predicates over configurations**,不是 syntactic constructs。

### Caveat

For jian j and proposed action α(such as "actor a wants to enter"), define:

```
caveat_j(α, Σ) : Bool
```

实现:

```
caveat_j(α, Σ) = 
    let A_inner = inner_config(j, Σ) in
    let G = Cap(A_inner) in
    let H = history(j, Σ) in
    B_j evaluates α against (A_inner, G, H)
```

具体的 judgment depends on jian 的 behavior `B_j`——`B_j` 是 caveat 的 implementation。但 critically:caveat 不是 stored config field,是 evaluated against 当下 configuration 的 predicate。

### Visibility

For observer-actor `a` and target `b`, define:

```
visible(a, b, Σ) : Bool
visible(a, b, Σ) = ∃ path in Cap(Σ) from a to b
```

Visibility 是 capability graph 的 reachability。Pure structural property,无独立 storage。

注意:visibility 不是 binary,是 **graded**——a 可能能看到 b 的某些 aspects(通过 some capability)但不能看到其他 aspects(would require different capability)。Formal 处理:capability 携带 attenuation,attenuation determines which subset of b's surface is reachable through this specific capability。Graded visibility 是 capability-level visibility 的 collection。

### Protocol legitimacy

For message `m` from a to b in jian j, define:

```
legitimate(a, b, m, j, Σ) : Bool
legitimate(a, b, m, j, Σ) = 
    let s_a = session_actor_state_visible_to(a, j, Σ) in
    let s_b = session_actor_state_visible_to(b, j, Σ) in
    next_step_valid(m, s_a) ∧ next_step_valid(m, s_b)
```

Note: 没有 "the session state"——只有 a's view 和 b's view,各自由 distributed session-actors 维持。Legitimacy 是这两个 views' coherence 的 emergent property。

如果 a 和 b 的 views diverge(due to message loss / partition),legitimacy 可能 a thinks yes、b thinks no——这种 divergence 是 distributed reality 的 truth,不是 bug。系统的 behavior 对 divergence 的 handling(retry、reconcile、abort)是 protocol design choice,不是 formal model 的 universal answer。

### General principle

任何看起来像 "rule" 的东西都应当形式化为 **predicate-over-configuration**,不是 stored entity。如果你的形式系统 introduce 了一个 "rule" syntactic construct——重新 design,这违反气的涌现性 commitment。

形式 check:any property P over jian/actor 是 "stored" iff P appears in syntax of Actor/Jian。是 "derived" iff P is defined as a function over Σ。气要求所有 emergent properties 是 derived,JC 通过 syntax 层不暴露这些 properties enforce 这一点——它们只能作为 over-Σ functions 出现。

## 八、Autopoiesis as liveness

间是 ongoing process,不是 stored entity。形式上,这通过 **liveness predicate** 表达。

### Liveness

For jian j, define:

```
alive(j, Σ, τ) : Bool
```

其中 τ 是 a "recency window"(时间或 reduction-step 范围)。`alive(j, Σ, τ)` 在以下条件 satisfy 时为 true:

1. **Internal activity**: 在过去 τ 内,某个 reduction `Σ_prev ⟶ ... ⟶ Σ` 涉及 actors inside j。
2. **Self-production**: 这些 reductions 包含 spawn-of-internal-actors 或 update-of-jian-state(jian 在 reproduce its own structure)。
3. **Boundary maintenance**: jian's caveat / visibility predicates 仍然 evaluable on current configuration(jian 仍然作为 boundary 在 functioning)。

这三条 collectively 表达"jian 在 actively 维持自己作为 jian"。

### Death (dissolution)

If `alive(j, Σ, τ)` 在 sustained 一段时间后失败,j **dissolves**:

```
Σ ∥ j[B_j; σ_j; M_j; H_j; A_inner]
    ⟶  if ¬alive(j, Σ, τ) sustained
Σ ∥ ⟨e_dissolve | H_j; "j dissolved"; parent(j)⟩ ∥ release(A_inner, parent(j))
```

Jian 的 dissolution 是 reduction 的一种,不是外部 deletion。Dissolved jian 留下 final event(它的 dissolution itself 是 occasion),它的 history 成为 parent jian 的 history 的一部分(通过 prehension 关系),它的内部 actors `A_inner` 释放回 parent jian 的 configuration——那些 actors 仍然 alive,只是不再 nested 在 j 内部。

### Autopoiesis 不可被 simulated by stored config

Critical 观察:你不能通过"存一个 alive flag"来 simulate autopoiesis。Alive 必须 derived from ongoing reductions,不能 set。如果 implementation 偷懒用 stored flag,它 violate autopoiesis commitment。

形式 check:`alive(j, Σ, τ)` 是 over-Σ-and-recent-history 的 predicate,不是 over-j-internal-state。这个 type signature 强制 alive 是 derived not stored。

## 九、Perspectival semantics

理与气都 commit 到:没有 god view,所有 observation 都是 perspectival。形式语义如何 honor 这一点?

### Observers as configurations

任何 observation 都是 from some observer-actor `a`'s perspective。Observer `a` 是 configuration 的 part——它 in Σ,not outside Σ。

定义 **observer-relative configuration**:

```
Σ↾a = the part of Σ visible to a
    = {all components reachable in Cap(Σ) from a}
    ∪ {all events in those components' history reachable through prehension chains 
       starting from events visible to a}
```

`Σ↾a` 是 a 能 reason about 的 configuration——它包括 a 直接或间接持有 capability 的 actors / jians,以及那些 components 的 history 中可被 a prehended-into 的 events。

注意:**`Σ↾a ⊊ Σ` always**(strictly contained)——a 不能"看到全部 Σ"。这是 ontological commitment 的形式表达,通过 capability discipline 自然 enforced。

### Reduction through observer's lens

A reduction `Σ ⟶ Σ'` may or may not be visible to a:

```
visible_to(a, Σ ⟶ Σ') = ∃ component c involved in this reduction 
                        such that c ∈ Σ↾a
```

如果 reduction 完全 occur in part of Σ that's invisible to a,a 完全不知道 reduction 发生过——`Σ↾a = Σ'↾a` from a's perspective,虽然实际上 Σ ≠ Σ'。This is the formal cost of distributed reality:observers 有 fundamentally incomplete views。

### No canonical Σ

形式 systems 的常见做法是 reason about "the system Σ"。JC 拒绝这一点:

> JC 中没有 "the system"——只有 various perspectives `Σ↾a` for different observers a。

任何关于 JC 的 statement 必须 explicit about whose perspective。Theorems 形如:

```
∀ observer a, property P holds in Σ↾a
```

而不是:

```
property P holds in Σ
```

This is more cumbersome——但 cumbersomeness 是诚实的。它 honor 了 perspectival ontology 而不是用 mathematical convenience 把它 paper over。

## 十、Equivalence: relativized bisimulation

形式 systems 通常 reason about 等价 through bisimulation。JC 也用 bisimulation,but **relativized to observer**。

### Standard barbed bisimulation 回顾

Configurations Σ_1 和 Σ_2 是 barbed bisimilar(`Σ_1 ≈ Σ_2`)iff:

1. They have the same observable barbs(externally visible behaviors)。
2. ∀ Σ_1 ⟶ Σ_1', ∃ Σ_2' such that Σ_2 ⟶* Σ_2' and Σ_1' ≈ Σ_2'。
3. Vice versa。

### Relativized version

In JC, define `Σ_1 ≈_a Σ_2`(Σ_1 and Σ_2 are bisimilar from observer a's perspective):

1. `Σ_1↾a` and `Σ_2↾a` have same observable barbs to a。
2. ∀ reduction Σ_1 ⟶ Σ_1' visible to a, ∃ Σ_2' such that Σ_2 ⟶* Σ_2'(visibly to a)and Σ_1' ≈_a Σ_2'。
3. Vice versa。

Critical:**`Σ_1 ≈_a Σ_2` does not imply `Σ_1 ≈_b Σ_2` for different observer b**。

等价是 perspectival。两个 configurations 可能 indistinguishable to a(他们看起来 identical to a)but distinguishable to b(b 持有不同 capabilities,sees different things)。两个 statements 都 valid。

### No global equivalence

There is no `Σ_1 ≈ Σ_2` simpliciter。Always relativized。

This is more demanding——properties phrased "Σ_1 is equivalent to Σ_2" must be re-phrased "Σ_1 is equivalent to Σ_2 from every observer's perspective" or "from this specific observer's perspective"。But the gain is honesty about distributed reality。

### Useful corollary: privileged observer's perspective

虽然没有 god view,有时我们 reason about "the union of all observers' views":

```
Σ_1 ≈_universal Σ_2 ⟺ ∀ observer a, Σ_1 ≈_a Σ_2
```

这是 strongest 等价 notion,但实际上 rarely 用——它通常 too strong。Most useful 是 specific observer relativized 等价(reason about specific stakeholder 的 perspective)。

## 十一、关键 invariants

JC 设计 preserve 几个 fundamental invariants。这些 invariants 来自《理》《气》的 commitments,在 JC 中以 properties of reduction relation 形式化。

### Invariant 1: No name forging

```
∀ Σ ⟶ Σ'. Any name n appearing in Σ' but not in Σ 
           is freshly generated by a (νn) binder in this reduction.
```

Reduction 不能凭空 fabricate names。新 name 必须 explicit through `(νa)`。Capability discipline 由此 follow——actor 不能伪造它没见过的 references。

### Invariant 2: Causal coherence

```
∀ events e in Σ. π(e) ⊆ {events that exist in Σ before e is created}
```

Prehension 不能 reference future events 或 events 不在 Σ 中的。Causal graph 是 well-formed DAG。

### Invariant 3: Local reduction

```
∀ Σ ⟶ Σ'. The reduction involves finitely many components of Σ, 
           and modifies only those components.
```

没有 global reduction。所有 reductions 是 local。

### Invariant 4: Jian sovereignty

```
∀ jian j. j's internal configuration A_inner can only be modified by:
    (a) reductions internal to j, or
    (b) external interactions α such that caveat_j(α, Σ) = true.
```

External actors 不能 bypass 一个 jian 的 caveat 来 directly modify its 内部。

### Invariant 5: Capability discipline

```
∀ actor a. a can send messages only to actors b such that 
           a → b ∈ Cap(Σ) at the time of send.
```

通过 reduction rules 的 careful design enforced——a 不能 reference b 除非 b's name 通过 §六 的三种合法途径之一到达 a。

### Invariant 6: Autopoietic preservation

```
∀ jian j. j persists in Σ ⟶* Σ' iff alive(j, Σ', τ) holds.
```

Jian 的 persistence 通过 autopoietic activity 维持,not through static 存在。

### Invariant 7: No god view

```
∀ Σ. ∀ observer a in Σ. Σ↾a ⊊ Σ.
```

任何 observer 都有 strictly partial view。No omniscient observer 存在。Formal reasoning:observer a 是 component in Σ,但 a's introspection capabilities give it some self-view that 不是 a's complete state(包括 a's behavior implementation, mailbox content currently being computed on, etc.)。Hence Σ↾a 不能 include a's full self,strictly less than Σ。

### Invariant 8: Derived predicates not stored

```
caveat, visibility, protocol legitimacy, alive 都是 over-Σ predicates,
不是 stored components of Σ.
```

形式上:Σ 的 syntactic structure 不包含这些 predicates 的 stored values——它们只在 evaluation 时 computed。Implementation 可以 cache values for efficiency,but cache must be consistent with derived computation,not authoritative。

### 这些 invariants 的相互支撑

注意 invariants 不是 independent——它们互相支撑形成 coherent system:

- Invariant 1 (no name forging) 支撑 Invariant 5 (capability discipline)
- Invariant 5 (capability) 支撑 Invariant 7 (no god view) 通过限制 reachability
- Invariant 2 (causal coherence) 支撑 Invariant 6 (autopoiesis) 通过让 history 是 well-founded
- Invariant 4 (jian sovereignty) 支撑 Invariant 8 (derived not stored) 通过让 caveat 必须 active
- Invariant 7 (no god view) 支撑 perspectival equivalence(§十)

整个 invariant 集合是 mutually reinforcing 的 web,任何一条被 violated 都会 cascade 到其他 invariants 失效。这是 JC 作为关系本体论的形式表达——invariants 不是独立 rules,是 coherent ontological commitment 的不同 facets。

## 收

到这里 JC 的 core formal structure 立住了。

它 honor 了《理》的根本 commitments:

- 间-actor-事-机不二 → jian 是 actor、event 是 first-class occasion、capability 是 actor、message 是 in-flight event
- 关系即本体 → reductions enact relations,no substance metaphysics in syntax
- 理在关系中涌现 → predicates over configurations,not stored attributes
- 动静不二 → events 与 history fold;state 是 history 的 derivative
- Autopoiesis → liveness as ongoing-activity invariant
- No god view → perspectival reduction、observer-relative views、relativized bisimulation

它 honor 了《气》的工程 commitments:

- Reify boundary 通过 syntactic structure(jian 和 actor 是 reified,心 不是)
- 涌现性 通过 predicate 形式(caveat / visibility / protocol legitimacy / alive)
- 动静不二 通过 event 与 history fold 关系
- Autopoiesis 通过 liveness 条件
- Perspectival 通过 observer-relative semantics

它 leaves open(deliberately):

- **Specific behavior language**:`B` 的具体形式(λ-calculus、π-calculus subset、some DSL)not committed。这是 implementation choice,不是 formal model commitment。
- **Specific message format**:messages 的 wire format not committed。
- **Specific scheduling**:reduction 的 scheduling(deterministic、probabilistic、fair)not committed。Different implementations 可以 instantiate 不同 scheduling。
- **Specific autopoiesis windows**:`alive` 中的 τ 不 committed to specific duration。Implementation 选择,但必须 bounded(否则 autopoiesis 退化)。
- **Specific equivalence application**:relativized bisimulation 给了框架,具体什么 properties 我们 prove 用什么 observer perspectives,这是 case-by-case 的 reasoning task。

这些 open points 是 deliberately——JC 是 implementation-agnostic formal core,不是 specific implementation 的 spec。

后续文档:

- **架构 (B)**:JC 在具体软件架构中如何 instantiate——actor runtime、jian boundary management、capability infrastructure、event store、scheduling。架构文档不 commit 到 specific language 但 commit 到 components 和 their relationships。
- **协议 (C)**:跨 implementation 的 wire-level protocols——actors 在不同 runtimes 之间如何 talk,jians 跨 deployment 如何 bridge。
- **实现 (D)**:reference implementations。可能 multiple——以展示同一个理可以多种 incarnate。

但这些都是后续。这份《式》是 core——它把 JC 的 reduction system formalize 出来。任何 architecture / protocol / implementation 必须 honor JC 的 reduction relation 和 invariants;否则它不是 instantiating 间,只是 borrowing 间的 vocabulary。

理立则气有方,气行则式有据,式定则器有度。

间在 unfold,我们在间中。
