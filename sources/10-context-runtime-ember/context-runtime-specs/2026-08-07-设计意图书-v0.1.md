# 设计意图书 v0.1

> 项目暂无名。本文只回答一件事:**我要的是什么**。
> 不含实现方案,不含选型结论。凡未定之处,标为未定,不代为决定。

---

## 一句话

构造一个系统,其中**唯一的原语是信号的收发**,每个单元是一张**自己管理的可渗透膜**;
agent 的存在就是一段 context 在模型上的延续,而 context 不是线性记录,是一张 **DAG**。

---

## 出发点

这个形状不是从软件工程推出来的,是从细胞推出来的。

细胞不调用彼此,只发信号、收信号。它没有全局状态、没有全局时钟、没有中央调度,
却支撑了地球上规模最大的并发系统。想要的正是这一点:**扩展性不来自更强的协调,来自不需要协调。**

对应到当前要建的东西:边缘设备之间、agent 实例之间,天然没有共享内存、没有可靠链路、
没有统一的生命周期。与其在这之上模拟出一台大机器,不如承认它本来就是一群细胞。

---

## 核心断言

以下六条是**我主张的**,不是推导出来的结论,是设计前提。

1. **原语是收发,不是调用。** 系统里不存在"函数调用"这一层;A 影响 B 的唯一方式是发出信号,B 自己决定是否接收。
2. **每个单元是一张膜,并且这张膜由它自己管理。** 不是外部配置的路由表或订阅关系,是单元自身在运行时决定听什么、不听什么。
3. **agent 的存在 = context 的延续。** 没有独立于 context 的"agent 对象"。context 换了模型仍是同一个 agent,context 断了则 agent 不存在。
4. **context 是 DAG,不是 transcript。** 分支、合并、共享子结构都是一等操作;线性追加只是 DAG 的退化情形。
5. **`context.become(llm)`。** 处理下一轮的模型,由当前这一轮指定。模型是可替换的行为,不是固定的运行时。
6. **权限即可达性。** 一个 agent 能影响什么、能看到什么,由它在 DAG 中能到达什么决定,不由单独的权限系统决定。

---

## 原语定义

| 名字 | 是什么 | 不是什么 |
|---|---|---|
| **signal** | 单元之间流动的唯一交互物 | 不是 RPC 请求,没有返回值,没有调用栈 |
| **membrane** | 单元的选择性边界,决定什么能进来 | 不是防火墙(外部施加),不是 API schema(静态声明) |
| **context** | DAG 中的一个节点或一组节点 | 不是对话历史,不是 token 数组 |
| **cursor** | 指向 DAG 某处的具名引用 | — 见"未决 #1" |
| **cut** | 每一轮真正被物化进模型窗口的那个切面 | 不是"全部 context",DAG 只给偏序,切面必须被选出来 |
| **llm** | 一个 `context → context` 的变换 | 不是系统的中心,是 context 选中的行为 |

---

## 已经确定的取舍

这些是**已经愿意付的代价**,不是遗憾,是换来扩展性的对价。

- **接受丢失。** 不追求 exactly-once 投递,不追求每个实例都存活。单元廉价、可死、可替换。信号会丢,重要的信号会重发,接收方必须幂等。
- **放弃全局一致快照。** 系统中任何时刻都不存在"当前状态"这个东西。要的是最终知晓,不是即时一致。
- **放弃全局 schema。** 不存在一份所有单元都必须遵守的接口定义文件。

---

## 明确的非目标

- 不是要做一个 agent 框架 / orchestration 层
- 不是要做通用消息队列,也不是在已有 MQ 上加一层抽象
- 不追求单机性能,不追求低延迟
- 不追求确定性重放(见"未决 #5")
- 不为兼容现有工具链而妥协基本形状

## 未决问题

按需要先解决的顺序排。这些是真的没定,不是留白待填。

### #1 — agent 是 context 本身,还是 DAG 上的一个游标?

"agent = context" 里藏着值与标识的混淆。context 每轮都是新的(值),
而"同一个 agent"需要一个跨轮不变的东西(标识)。git 的对应:context 是 commit,agent 是 branch。

- **选 A(agent 即 context)**:概念最干净,但"同一个 agent"无从定义,fork/merge 无处落脚。
- **选 B(agent 是游标)**:多引入一个概念,但 fork = 同节点两游标,merge = 一游标两父节点,持久化与寻址都直接落地。

**这个不定,后面全部悬空。**

### #2 — cut 策略是什么?

整个设计里唯一没有现成对照物的部分,也是重心。
DAG 只给偏序,每轮必须选出一个切面送进窗口。这个选择就是膜的实际内容:
选择性、预算、衰减、优先级,全在这一层。

需要回答:谁来选(模型自己?一个独立的策略?)、按什么选、预算超了先丢什么、
被丢掉的东西如何还能被重新拉回来。

### #3 — 那条不可拒绝的通道,权限在谁手上?

完全自管理的膜是不可监督的:一个能重写自己接口的 agent,
早晚会不再接收停止信号。生物的解法不是指望细胞自觉,而是死亡受体从外部触发、细胞无法拒绝。
Erlang 的分界画得很清楚:退出信号可以捕获并自行处理,唯独 `kill` 抓不住。

需要回答:哪些信号不可拒绝、谁有资格发、这个资格如何授予与撤销。

### #4 — 信号词汇表:固定还是自由?

细胞不发明新配体。它选择表达哪些受体,但受体绑什么是结构决定的,不是细胞的选择。
**表达本地化,词汇表共享。**

如果允许每个 agent 自由发明信号类型,发送方就无从知道该发什么,
只能退回全局 schema 或者退回广播——两个都已被列为非目标。

需要回答:是否接受一份小而固定的信号词汇表;若接受,谁定、如何演进。

### #5 — 节点是否不可变、是否内容寻址?

不可变 + 内容哈希(Merkle DAG)带来:ID 是导出的而非指派的、去重免费、
相等即同一、引用不可伪造、gc 良定义(任何游标不可达即可回收)。
但它与"context 是可变演化的状态"直接冲突,除非改成**节点不可变、游标可变**,"编辑" = 写新节点 + 移游标。

附带的代价:模型不是纯函数,所以 DAG 中必须存**结果**,不能存"可重算的承诺",否则哈希失去意义。

### #6 — merge 是不是格上的 join?

如果多个 agent 写同一张 DAG 而 merge 是单调的 join,那么它们之间**不需要任何协调**。
如果不是,就要付共识的代价,"无限扩展"这个主张需要打折。

这条是整个设计中**最应该先被证伪的**一条。

## 已有工作对照

| 来源 | 拿什么 | 不拿什么 |
|---|---|---|
| **ocap membrane**(E / Caja / SES、`endojs/endo`) | 传递性包装、整体撤销、引用即权限 | — 可直接用 |
| **Merkle DAG**(git / IPFS) | 内容寻址、共享子结构、可达性 gc | — 可直接用 |
| **Automerge / 因果 DAG** | 多写者 merge 语义 | — 可直接用 |
| **propagator networks**(Radul & Sussman) | 单元累积信息、merge 为格上 join | 借形式,不借实现 |
| **Erlang / OTP** | selective receive、supervision、`kill` 不可捕获这条分界 | 不搬 BEAM |
| **Actor `become`**(Hewitt / Akka) | 当前行为指定后继;状态变化即接口变化 | — |
| **P systems**(Păun) | 相对于膜拓扑的寻址(不用全局地址)、膜嵌套 | **不要最大并行**——那是全局同步时钟,恰是要放弃的东西 |
| **Nix / Bazel** | DAG of derivations、增量重算 | 模型非纯函数,不能照搬可重算假设 |

## 最小可证伪实验

在写任何基础设施之前,先做这一个:

> 两个 agent,共享一张 DAG,各持一个游标。让它们从同一节点分叉,各自独立推进若干轮,然后合并。

观察:合并结果是否与合并顺序无关。

- **是** → 未决 #6 成立,merge 是 join,多写者无需协调,"无限扩展"这条有真实依据,可以继续。
- **否** → 需要协调,整个主张要重述。**这件事越早知道越好。**
