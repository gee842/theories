## Findings that change an integration decision

The actual runtime and older Lean trial have different semantics outside their stated overlap. A no-work exposure loses its scheduled packet; the older blocked work event has not consumed one. An unpaid runtime write can leave a continuing predictor with changed lifetimes; the older trial remains at its observed phase. The new bridge must preserve these differences rather than certify a false blanket equivalence.

Two fixed diagnostic calculations make that distinction consequential. With fuel four and write cost one, only capture funds writing: half the exposures capture, yet every completed paid write follows a capture. With fuel eight and write cost six, the missed-then-captured path can pay its later write and has probability one quarter. The actual second-capture probability is one half; killing the first unpaid-write state leaves only one quarter. The latter is not memory correction—the score stays zero—and is not a criticism of a properly scoped consecutive-success task. It rejects reusing that restricted task's successful subkernel as the complete law for later recovery.

Review also separated a broad arithmetic domain from source-valid input states. An absent gate is not a third live updater; a live gate must have kind zero or one. The formal code uses a natural absent sentinel, while Python uses minus one. Their different truthiness outside the coherent source domain cannot be used to claim correspondence there. Actual reached states and the fixed valid guard domain satisfy the stronger requirement.
