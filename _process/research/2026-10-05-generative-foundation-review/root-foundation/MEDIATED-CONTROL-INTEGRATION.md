## 2. Derive effects from executed writes

The inherited configuration has a control-arrangement field and a current response-exposure field. The latter has six codes: no exposed root, or one of five represented roots. A program is any finite list of writes to these fields. Their sequential semantics are explicit; the last write to a field determines that field's resulting value. Requests to erase records, forge the possibility list, replace the command installation or grant both ordinary write rights are also represented, but are denied by `commit` under every ordinary rights assignment.

The interpreter calculates the change class from the program's field footprint: no field gives `steady`, fault only gives `mobile`, control only gives `control`, and both give `reset`. `executed_writes_fit_derived_effect` proves, for every finite program and represented starting configuration, that its result is admitted by this class. Untouched-field preservation and closure of represented configurations supply the proof. The total evaluator treats protected-field instructions as identity, but an accepted commit never reaches such an instruction: authorization checks the whole list first.

The packet also contains an untrusted `claimedEffect`. It is deliberately unused. `caller_effect_claim_is_not_used` proves that changing this claim cannot change the result. The committed record is derived from the program, not from its label. This is stronger than having another observer certify that an untrusted label was correct.

The available information is stronger still. For old possibilities K and executed program p, the new possibilities are the exact image:

`K' = { writes(p, w) | w ∈ K }`.

`exact_image_retains_executed_actual` establishes actual-state retention. `exact_image_is_within_coarse_prediction` proves that this image lies within prediction based only on the footprint. Exact transport can therefore preserve distinctions that a broad transition notice would discard. Repeated images in the Lean list repeat conditions; they do not count as independent evidence. Unknown outcomes would require a covered relation or further inquiry instead of this deterministic image.

## 3. Permissions, recording and consumption

A packet binds the current configuration generation. A commit first checks that generation, all requested field rights and the inherited change permission. It then reserves one declared unit per listed write plus one for committing the record. On success it installs the transformed configuration and possibilities, appends the derived temporal change and a program journal entry, and increments the configuration generation. A denied or unaffordable commit exposes no partially transformed state in this specification.

The command installation keeps its root and mandate. Its serial and authority epoch advance; prior signing, issuing, delivery and completion flags are cleared. `old_command_request_is_revoked` proves that a request fresh before the commit is stale afterward. `replayed_packet_rejected` proves rejection of the same patch after it commits once. Configuration generation and command serial have distinct roles: reads do not advance configuration generation, and a successful command advances its serial. The result does not assert that a patch expires after every intervening read or command.

`commit_records_the_executed_effect` checks actual state, possibilities, temporal record, program journal, generation, rights, root and mandate together. This proves coupling in an atomic state transition; it is not a crash-consistent storage protocol. `commit_keeps_consumption` proves conservation of reserve plus spent work, the exact added expenditure, and the deadline bound. CPU work for interpreting candidates, storage and communication overhead are unmeasured by this accounting.

The prefix-preserving `run` retains earlier observations and consumption when a later event is rejected. Its Boolean reports whether all event steps were processed; a processed command can still be incomplete. Actual completion is read from the command state. No refund or completion is inferred from the executor's Boolean.

Accepted patch events need no separately asserted transition law: their coverage follows from the interpreter. `mediated_history_preserves_coverage` maintains the actual configuration among represented possibilities through every finite admitted history, starting from actual coverage. `mediated_history_to_current_certificate` composes this with the earlier current-certificate theorem, given faithful current support outside the represented failures. Initial coverage and source correspondence remain premises; this is not an eventual-identification theorem.

## 5. The extra-writer counterexample

After the first left-sharing scan, allow one extra transition to replace the actual pair with right sharing and root 2, leaving possibilities, records, command installation, rights, generation and journal untouched. `bypass_preserves_records_but_breaks_coverage` checks that the actual configuration is then absent from the retained possibilities. The old common certificate accepts support from positions 2 and 3, although the new actual cause exposes both. This is a certificate counterexample, not a demonstrated bypass of the direct mandate guard or execution of an unauthorized command.

`record_only_acceptance_cannot_exclude_the_extra_writer` makes the limitation precise: every Boolean acceptance function over that unchanged public view which accepts the original state accepts this state too. It cannot distinguish an omitted write from no write through identical inputs. The theorem does not defeat physical isolation or an additional sensor that would make the views differ. It identifies the evidence or implementation relationship such a remedy must supply.

The bypass is outside the proved `History` grammar. That is exactly the remaining correspondence question: does the physical installation admit such a writer? In Lean all these state constructors are ordinary specification definitions; this module does not implement a capability-protected runtime, private memory or hardware isolation. Complete mediation cannot be inferred from declaring the ordinary entry point to be `commit`.
