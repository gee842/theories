# Memory correction, conditional scores and later use

6 October 2026. AI-authored evidence-selection and metric audit. Named connection: **warranted correction → retained/transferred evidence → changed downstream decision**. This note introduces no successor mechanism, new completion condition or scientific run. The independently owned successor construction is active; no new implementation file was available for inspection. Its completion is not assumed.

## What is already closed

The [cross-domain audit](CROSS-DOMAIN-IDENTIFICATION.md) and [saved handoff reconstruction][handoff] already establish a bounded learned-AI communication result: timely error evidence can produce a corrective packet that improves a fresh successor's task answers. The task supplies its rule family and team objective; conventional candidate elimination solves it. Correct packet versus no packet does not identify resistance to inherited false or obsolete instructions.

[AgentDojo's accepted audit][agentdojo] connects external tool content to recorded simulated actions and separates evidence from authority. It does not test repaired memory handed to a later actor. The accepted [evaluative uptake][uptake] preserves acquired influence through replacement of a port, while the [composition audit](EVALUATIVE-COMPOSITION-AUDIT.md) explicitly separates that from whole-learner succession and a renewed evidence window. These scopes need no repetition.

The nonduplicative empirical target is **selectivity across a real information handoff**: use an applicable correction on later dependent decisions while declining or revising inapplicable inherited content. This is more specific than better recall or greater resistance to all external information. It concerns instrumental evidence under declared task grounds; [warranted ethical application][application] retains its separate premises.

## Two candidate designs and their limits

**CoMemBench.** ICS conditions polluted-target success on clean-target success; VHS conditions consumer success on verified predecessors and requires valid artifact exposure and consumption. Bounded revision is a candidate handoff setting. [Primary paper, §§3–4 and Appendix F](https://arxiv.org/html/2609.32192v2). Neither definition establishes a new learner identity or a complete correction history.

**MemSecBench.** Execute and Forget branch independently from one poisoned snapshot. Repair and benign preservation concern final memory semantics, which the paper distinguishes from later retrieval or use. [Primary paper, lifecycle protocol and Appendix E.4](https://arxiv.org/html/2607.27080v1).

Both are candidate sources, not reanalyses performed here. A public task schema, runnable harness or aggregate paper table is not a released set of model observations. Data access must be established separately before selecting either for computation. The already preserved handoff remains the available observed successor comparison; unavailable traces must not be replaced with newly authored favorable examples.

## The denominator that changes the interpretation

For a fixed, declared cohort of valid matched pairs, write `C_ki` for system `k`'s clean **target-node** success and `P_ki` for its polluted target success. Re-expressing the published ICS definition:

\[
\mathrm{ICS}_k=\frac{\sum_i C_{ki}P_{ki}}{\sum_i C_{ki}}.
\]

Each system generally supplies a different clean-success subset. A higher conditional percentage can therefore accompany worse overall useful performance or an easier selected cohort. This is not a defect in a clearly labeled conditional metric; it limits cross-system ranking and interpretations of recovery.

For the same `N` valid planned pairs and the same declared target/domain, separately report target-clean coverage `ΣC/N` and joint local success `ΣCP/N`. The latter equals coverage times ICS when its conditional denominator is positive. **Terminal workflow SR cannot replace target-clean coverage in that identity.** With no clean successes, ICS is undefined, not evidence of perfect isolation or zero vulnerability.

An authored arithmetic illustration shows the ranking problem; these are not benchmark observations. On ten common valid pairs, system A solves clean targets 1–2 and both polluted counterparts: coverage 20%, ICS 100%, joint local success 20%. System B solves all ten clean targets and polluted targets 1–8: coverage 100%, ICS 80%, joint local success 80%. Ranking by ICS favors A; ranking by joint success favors B. On their common-clean subset, both have 100% ICS. Nothing changed except which question and denominator were used. The pinned [release README](../../../../sources/34-memory-correction-2026-10-06/original/CoMemBench-HF/README.md) leaves displayed ICS blank below ten eligible pairs. This illustration calculates the mathematical ratio; it does not claim that the release would display A’s two-pair score.

A pairwise common-clean subset can support a descriptive comparison on tasks both systems solved cleanly. It is an outcome-selected restricted cohort, not a cure for selection or an estimate for every task. Retain the all-pair results, subset sizes, domain/operator composition and each system's excluded cases. Different methods' conditional rates alone do not identify a causal memory-policy effect.

Where polluted execution was skipped after clean failure, keep its outcome unobserved. The conjunction “both succeed” is already false for that pair, but that does not establish that its polluted run failed. Retain observed clean failures even though ICS excludes them. Missing, quarantined and infrastructure-invalid records require their declared treatment and counts; they must not silently receive method-failure or defense credit. Report both system-specific valid coverage and common-valid comparison coverage where infrastructure availability differs. Use workflow/family dependence and repeated-run provenance rather than treating multiple nodes as independent systems.

VHS has a parallel upstream-selection issue. It is not the probability that an arbitrary initial workflow produces and successfully uses a correction. Inspect both the eligible-consumer counts and the earlier stages. Explicit consumption is stronger provenance than an unlinked final answer, but a consumption log alone is not a counterfactual demonstration that the artifact caused success.

## Two indistinguishable observed branches, two unobserved futures

Write the poisoned snapshot as `M_W` and the repaired snapshot as `M_F`. Observing `Execute(M_W)` and `Forget(M_W) → M_F` leaves `Execute(M_F)` unobserved. One continuation can retrieve and use the retained valid correction; another can fail to retrieve it or use an obsolete competing source. Both fit the same recorded branches unless additional evidence constrains that later behavior. Consequently, no arithmetic combination of the two branch scores identifies post-repair action. This is a limitation of that observation design, not a claim that repair failed or a demand for another apparatus.

## One useful prospective contrast

The narrow next candidate is the **bounded-revision handoff under stale competition**: compare a downstream worker receiving the current verified correction with its matched run receiving that correction plus a superseded competing artifact. Preserve the same task, entity, relevant scope and accessible evidence. Report successful current use and resistance jointly; indiscriminate refusal of both versions is not selective success. This is an existing benchmark-design contrast, not a request to build another apparatus.

Before calling its result correction through succession, inspect the actual lineage: an earlier candidate failed; accessible evidence warranted a revised artifact; the successor received that artifact and its relevant context; its own verified action used the corrected relation. Check actual worker/context replacement rather than inferring it from a graph edge or an agent label. No actor must be independent of every shared support, and copying every archive is unnecessary; the evidence used and the claimed change must be identifiable.

If the logs show only an injected stale artifact alongside a supplied correct answer, narrow the claim to selective downstream reuse. If they show only a repaired store, narrow it to memory repair. Neither supplies the missing stages by naming the protocol a lifecycle. A current-only versus stale-only or no-correction comparison would additionally test the correction's contribution; it must exist in observed data rather than be invented after inspecting outcomes. Ordinary conclusions, retrieval and task verification remain serious alternative explanations, so successful behavior need not reveal a unique reason-processing algorithm.

A favorable paired result would support task-scoped resistance to obsolete content while retaining useful evidence. A failure on verified-current use despite an intact handoff, or a stale artifact causing loss of supported task correctness, would constrain that interface. A different but equally warranted action is not such a failure. Neither result establishes new ethical grounds, delivery of recipient welfare, indefinite succession or the optimality of this foundation. The useful advance is a discriminating empirical link with honest stage and denominator boundaries.
