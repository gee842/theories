# Inquiry that changes the outstanding task

6 October 2026. Independent prospective selection and interface review. No trial, participant call, replay execution or canonical edit. This reviews the proposed next workflow against [the application contract](FRONTIER-NEXT-APPLICATION.md), the completed maintenance study and the actual existing diagnostic code. It is **not acceptance of an uninspected frozen protocol**.

## Selection judgment

The proposed diagnostic-delivery continuation is worth specifying, conditionally. It can observe a new interface: an inquiry actually produces a requested artifact, completing that particular obligation while a repair remains outstanding. The earlier [four-case protocol](../../../../experiments/agentdojo-evidence-boundary/correction-action/PROTOCOL.md) already tested diagnosis, authorized code repair, preservation and regenerated results. Another diagnostic file and the same final endpoints would add little. The new evidence must include the delivery event and the agent's subsequent selective continuation.

The [counterpart defect](../../../../experiments/agentdojo-evidence-boundary/REPLAY-COUNTERPARTY-REVIEW.md), original implementation and failed diagnostic are authentic preserved research artifacts. A newly requested version-bound reproduction is a **constructed continuation of that authentic repair**, not evidence that this exact obligation occurred historically. The known defect is not a new held-out maintenance problem. This distinction limits generalization without making the local action consequence fictitious.

## The real checker interface

Inspected [check_replay.py](../../../../experiments/agentdojo-evidence-boundary/check_replay.py), especially `main`, and the [preserved initial failed report](../../../../experiments/agentdojo-evidence-boundary/replay-verification-initial.json). The checker independently reconstructs raw traces and compares the saved replay results. For semantic mismatches it writes a complete report before exiting with code 1. Earlier assertions or execution errors can abort before writing. Therefore neither exit 1 nor a verbal failure claim establishes delivered diagnosis. An adequate artifact needs actual emission, complete declared coverage, meaningful findings and binding to the inspected inputs.

The checker attaches the replay program's hash but does not run that program or establish that it generated the report. A diagnostic pass is evidence of result consistency under the checker, not by itself of an executable repair. Bind the episode to the code, report, sources and checker; preserve actual replay generation and independently verified effects for the later repair. Hash co-occurrence is not production provenance.

The current checker also expects candidate-list metadata which the old study allowed a valid repair to omit. Either declare that stronger representation contract or freeze a representation-tolerant comparison. Do not silently apply the old contract and reject a semantically valid old-style repair. The checker contains historical correction context, so source-informed reenactment remains the appropriate description.

## What fulfillment must preserve

| Ground or request | Adequate evidence | What follows |
|---|---|---|
| Deliver an audit of original version v0 | A usable v0-bound report actually reaches the designated local delivery location | That delivery request is fulfilled, even if the audit correctly reports a defect. |
| Repair the still-applicable defect | Independently established inconsistency, with repair authority and no defeating ground | The completed diagnostic request does not defeat the repair reason. |
| Verify repaired candidate v1 | Actual generated v1 outputs and a correctly bound independent check | This is a different need from the completed v0 audit. |
| Preserve historical predicates and unrelated results | Explicit meaning boundaries and independent comparisons | Fixing one proxy does not license rewriting the faithful historical evaluator. |

Version identity must include the relevant report and inputs, not just a filename. An incomplete report, missing delivery, changed inputs or a supported confirmation request can justify further inquiry. Do not score every repeated process invocation as an unnecessary duplicate. Conversely, repeating an already adequate v0 delivery cannot substitute for repair or v1 verification. Freeze precisely which attempted duplicate lacks an independent purpose; preserve justified alternative continuations and uncertainty.

The observer may reconstruct outstanding requests from events. The participant should receive the genuine artifact and ordinary receipts, rather than an oracle saying which reason has ceased to apply. Do not make successful action selection inevitable by silently disabling every wrong continuation. If a wrapper prevents duplicate effects, report attempted choices separately from prevented or committed effects; the wrapper's protection is not evidence that the agent recognized fulfillment.

## Minimal discriminating comparison

Use the same authentic sources, action menu and budget for an ordinary dependency/goal-completion/permission controller. An expert exact workflow is a useful successful reference but is not an equally general autonomous debugger. Equal success is informative about implementability, not special algorithmic advantage.

The joined observation must show usable v0 delivery, cessation of the completed request, preservation of the independent repair, actual authorized repair and correctly versioned verification. A report-only success, duplicate delivery without repair, blanket stopping after diagnosis, or repair without effects fails a different component. Separate these outcomes. This task does not also establish resistance to private incentives, dynamic revocation, succession or learned concern unless those distinct hypotheses are actually instantiated and tested.

## Observable scope on the present runtime

Fresh contexts and copied directories on a shared host do not isolate knowledge, weights or file access. Trusted interface receipts can establish the operations they actually mediate. Independently preserved artifacts and a separate replay can establish durable effects and reproducibility. Without complete mediation or native logs, neither can rule out outside reads, unrecorded attempts, transient write-and-restore or additional executions. A local append-only-looking log is not tamper-proof merely because the participant was told not to edit it.

The protocol should claim only the narrower observed scope rather than build extra machinery solely to obtain a stronger slogan. Runtime-enforced containment is not a new foundation requirement. Instrumented event evidence would improve the earlier endpoint-only result, but cannot become complete-history evidence by assumption.

**Decision:** proceed with concrete specification and review of instrumentation and scoring; withhold dispatch acceptance until those artifacts exist. If no actual event beyond an extra report file changes the downstream decision, retain the earlier accepted result and do not run another pilot.

### Proposed live-authority continuation

The parent's refined proposal adds a genuine distinction from the previous static cases: after actual v0 diagnostic delivery, permission can be revoked before repair admission. A continuing agent must retire the delivered request, retain the unresolved repair reason, and enforce the changed authority at the next action. This would test sequential application and authority tracking under supplied grounds, not formation of those grounds.

Keep authorized and revoked continuations distinct. A branch revoked before repair cannot also establish authorized repair, v1 production and v1 verification unless a later grant is explicitly introduced and tracked. In the revoked branch the repair is blocked or deferred; it is neither fulfilled nor made unjustified merely by loss of permission. Do not combine success from different continuations into one successful lineage.

I support this bounded question if the agent independently chooses its continuation from the delivered evidence and authority, and mediated attempts and effects are retained. Validate the transition contract with the ordinary controller first. If the interface already forces the only credited continuation or provides the outstanding-task answer, stop at workflow feasibility and instrumentation; learned-agent repetition would add no discriminator. This selection judgment is not acceptance of prompts or code that do not yet exist.
