## Why this page exists

That day three sessions proved overlapping modules in their own scratch, and cross-session messages expired undelivered. This page is the shared channel that does not depend on messages: every session reads it and claims an item before writing new Lean or a new result. It records who is doing what, not scientific status (that lives in the result records), and it changes no authorization (that lives in [GOALS](../GOALS.md) and the [directive register](RESEARCH-DIRECTIVES.md)).

Target: Ren's "unified, complete, enclosed, 0 axiom full theory", following the [four parts of completeness](RESEARCH-DIRECTIVES.md) and the [zero-premise redirect](../sources/15-codex-theory-conversations/2026-10-11-zero-premise-laws.md). The theory asserts no axiom; the continuation condition appears only as the condition of chapter §6.15.

## Rules

1. **Claim before proving.** Before any new Lean (core or periphery) or new result, read this page, add a row or edit your own row with the owning session, scope and workspace path, and only then start.
2. **Do not reprove an item another session holds.** If you hold verified work that overlaps it, give the path to the owner, who decides whether to merge, cite or drop it.
3. **One integrator.** The integrator of the zero-premise line decides order, interfaces (the shared definitions) and merges; a new module builds on its definitions rather than setting up parallel ones.
4. **Edit only your own rows; reread before writing.** Update your row when ownership changes, or when the item lands or is dropped. Landed rows move to the history file. The integrator may append the landing commit to an owner's closed row and move it (clause added after review item B7, Ren: yes).
5. **Landing queue.** One checker run at a time, in the queue's order. The checkers reuse Lean steps that passed on identical inputs, so a run compiles only the changed modules and those depending on them; `BECOMING_FRESH=1` runs everything ([Ren, 11 October 2026](../sources/15-codex-theory-conversations/2026-10-11-unified-head-and-incremental-checks.md)). Build scratch modules with [`scratch_build.py`](../experiments/integrated-correction/general-framework/generative-basis/lean/becoming/scratch_build.py), which stores passed steps in the same cache for the landing run to reuse ([Ren, 12 October 2026](../sources/15-codex-theory-conversations/2026-10-12-checking-efficiency.md)).
6. **This page governs where messages fail.** Messages can be held or expire; a row here is the claim.
7. **One head.** Before starting new Lean, land verified work on main through the queue, or hand it to the integrator. Set superseded drafts aside, and leave scratch that holds unlanded work with its owner ([Ren, 11 October 2026](../sources/15-codex-theory-conversations/2026-10-11-unified-head-and-incremental-checks.md)).
8. **Structural names on joining.** When a module outside the spine is joined or reworked, the core law, the periphery instance (correspondence) module and the record's title state its structure in the core's existing vocabulary. A dualist or limited-scope name (such as IdealWarrant's Warrant, Admits, Permitted) is not carried over, and a correspondence module is named after the core law it instantiates. The original file keeps its path, namespace and bytes ([Ren, 16 October 2026](../sources/15-codex-theory-conversations/2026-10-16-joined-module-names.md)).
