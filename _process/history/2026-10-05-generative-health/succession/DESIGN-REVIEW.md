# Adversarial design review: constructive discovery after succession

Prepared 5 October 2026 before the proposed experiment is available for implementation review. This is a design audit, not certification of code or results. Only this memo is being written in this review task.

## Minimal defensible advance

The strongest manageable target is **paid construction of a changed function after removal of the predecessor, with an experimentally isolated effect of transferred discovery means**. It need not claim unrestricted creativity, changing purposes, or endogenous institutional legitimacy.

The [situated-discovery experiment](../../../../experiments/situated-discovery/PROTOCOL.md) already lets a learner construct contextual policies within a finite grammar, pay for fresh tests, and face implementation costs. The [revisable-inheritance experiment](../../../../experiments/revisable-inheritance/PROTOCOL.md) already shows that a paid handoff can preserve distinctions required by a supplied later model. A new experiment must join elements they leave separate: learner construction, a real handoff that removes predecessor state, a changed task, and costs of preserving or rebuilding the means of further construction.

A compositional program or circuit environment is suitable for that narrow target. Its primitive vocabulary and task family will remain analyst-supplied. The claim should be “a successor constructs a new executable solution under these constraints,” not “the model creates possibilities outside every predeclared state space.” A program's encoding having existed in a large grammar does not eliminate constructive work; searching that grammar also does not establish new evaluative purposes.

## Freeze the chronology before seeing outcomes

1. Draw the initial task and run one specified predecessor learner using a paid interface. Preserve failed as well as successful attempts.
2. Stop at a declared handoff event. If initial success is required, record how often and at what cost it occurred. Do not silently drop failures.
3. Make retention choices using only information available by this point. Charge preservation and transfer before the later task is known.
4. Serialize the allowed transfer package and remove the predecessor. Successor state starts only from that package, public initial knowledge, and the specified remaining resources.
5. Draw or reveal the changed task according to a frozen family. Its actual realization must not determine which earlier intermediate was saved.
6. Let the successor inspect, rebuild, search, test, reject, and install through the paid interface. Use the same learner algorithm across arms unless the algorithm itself is the declared intervention.
7. Evaluate the installed result using outcomes that could not have influenced its selection. A later handoff or additional challenge would strengthen the claim, but one genuine handoff is sufficient for a bounded first test.

An analyst may specify correlated tasks to study reusable structure. That is not leakage if the realized later task remains unavailable to retention decisions. It is an intentionally favorable task distribution and must be paired with irrelevant or misleading reuse controls. An archive chosen using the realized future is a hindsight benchmark, not a feasible policy.

## A compact set of comparison arms

The most interpretable core separates transfer of components from transfer of experimental capacity. All arms should receive the same functioning first artifact and public primitive language, and all should have a paid route to build inquiry tools if they do not inherit them.

| Comparison | What is varied | What it can identify |
|---|---|---|
| Artifact with rebuilding | No preserved extra components or maintained laboratory; rebuilding is available at stated cost. | Baseline performance after inheriting a result. |
| Artifact plus components | Extra intermediate constructions are preserved; the laboratory still needs rebuilding. | Effect of transferred components, including their retention burden. |
| Artifact plus laboratory | Usable experimental interface and competence persist; no extra intermediate library. | Effect of ready discovery machinery, distinct from a stored solution. |
| Artifact plus both | Both means are carried across the handoff and charged. | Joint effect and whether the two transfers complement one another. |

Exact implementation can simplify these arms, but a composite “full inheritance” versus “nothing” comparison alone cannot identify which component matters. A never-search baseline can describe a frozen policy; it must not be the main evidence that artifact inheritance intrinsically prevents discovery.

If the setup contains no distinct laboratory state or rebuild action, do not name the component-library arm “maintained inquiry.” A library is one possible discovery support, not automatically the whole apparatus. Similarly, if authority is always granted, report it as an assumption rather than claiming to test institutional standing.

## The artifact is already information

A visible program contains its subexpressions. An artifact-only successor should be allowed to inspect source, extract components, and reconstruct intermediates at stated costs. A supposedly opaque artifact requires an explicit physical interface and an available, possibly expensive, reverse-engineering route if the model's technology permits one. Forbidding a reasonable extraction action creates the benefit of the richer archive by fiat.

Distinguish three transferred objects:

- subcomponents recoverable from the winning artifact;
- abandoned or neutral intermediate constructions absent from that artifact;
- experience or evidence about how constructions behaved.

These can have different benefits and prices. If the hypothesis concerns retained neutral intermediates, demonstrate that the useful transferred item really was unavailable from the winner alone and that its selection did not use later-task truth. “Neutral” should refer to an explicitly measured first-task criterion, not a retrospective label for something that became useful later.

The prior inheritance work also warns against artificial ignorance. Archive absence, retained structure, predecessor actions, readiness, and public costs may convey information. Successors should receive the cues their actual interface exposes. Alternatively, implement an interface that genuinely hides them and describe that restriction.

## Prevent oracle leakage and hidden predecessor state

The hidden task description, future task, and evaluator's full correctness table must not enter candidate ranking, archive selection, early stopping, or installation decisions. Learner observations must come from a declared interface with paid calls. An installed candidate is chosen by the learner's rule, never by selecting the best candidate according to final evaluator truth.

Executing a candidate's own known program to compute its semantics is different from querying the unknown target. Semantic deduplication can be legitimate if it uses only known primitive meanings and its computation is priced or explicitly unpriced. Deduplication against the hidden target, costless scoring on every target input, or a special proposal generator that reconstructs the planted target is not legitimate discovery.

If a formal target specification is publicly supplied, program synthesis can still be a real construction task. But then the experiment studies constructing an implementation from a known specification; paid observations do not discover the target's meaning. State which setup is used.

Serialize and inspect the transfer boundary. A successor object must not inherit private caches, retained training rows, global variables, callable closures, random-generator state revealing target generation, or source references beyond the declared package. A fresh learner initialized from the serialized package is preferable to clearing selected fields of the predecessor. Keep evaluator-only data separate from learner-visible logs.

## Charge the chronology, not just the final total

Use a branchwise ledger for creation, evaluation, preservation, transfer or loading, laboratory maintenance or rebuilding, candidate tests, and installation. Declare computation, compiler work, storage duration, and ongoing execution costs either charged or outside scope. Costs cannot become zero merely because a helper executes them during setup.

Any operation requiring a capacity must occur after that capacity is available. Each attempted candidate must be paid before its test results are observed. Reserve or account for installation work so “found an answer” is distinguishable from “delivered a working successor.” An installed macro cannot hide an uncharged primitive execution cost if the study claims operating efficiency; a macro may legitimately save search or construction effort without saving runtime.

Use equal lifetime resource caps and identical common pre-handoff histories for the main paired comparisons. Retention overhead should reduce resources available later. Equal caps are not equal actual expenditure, so report both allocation and realized spending. Common predecessor costs belong in every counterfactual lifetime ledger, although a shared simulated history can avoid recomputing them.

If no eligible test can possibly fit an arm's remaining budget, record an arithmetic feasibility bound. That is a useful resource result, not emergent evidence of failed reasoning. Offer a less restrictive budget where rebuilding is possible, otherwise the baseline merely witnesses the hardcoded resource threshold.

## Negative controls that can defeat the preferred story

**No useful reuse.** The later task can be solved cheaply from primitives but retained material is irrelevant. An indiscriminate retention policy should be able to lose through its earlier overhead. A null result here is not a defect to tune away.

**Misleading reuse.** A familiar component fits early observations but fails on independent cases. This checks whether inheritance causes premature acceptance, inadequate testing, or search fixation. A changed search order alone is not a new mechanism unless declared.

**Zero retention or rebuilding cost.** At relevant limits, the causal advantage should change in the direction predicted by the ledger. It need not vanish if stored components contain information unavailable to rebuilding, so specify which difference the control isolates.

**Matched irrelevant library.** Preserve equally costly constructions from another predecessor or unrelated first-task run. This distinguishes useful content from a generic benefit of receiving more objects or a different proposal distribution.

**Randomized component access after sealing.** Remove or reveal a nominated intermediate only after the archive is fixed, keeping the previous history constant. Where the interface permits a fair intervention, this tests content's causal effect without using the future task to curate it. Adjust or explicitly retain sunk transfer costs; do not inadvertently refund the treated arm.

**Independent reconstruction.** Allow the artifact-only learner to rebuild tools and recover usable components. If it catches up given adequate time and resources, the result becomes an efficiency or deadline advantage, not an absolute impossibility claim.

Do not require retention to win every control. The substantive claim is conditional: certain inherited structures preserve useful routes through particular changes, while preservation can also consume the margin needed for fresh construction.

## Evaluation and stopping rules

Declare a primary outcome: correct installation on the changed task by the deadline or budget after predecessor removal. Report first-task success, changed-task validation without installation, false installation, no installation, expenditures by stage, transferred material actually used, and service interruption separately. A larger candidate count is not a substitute for a new working function.

For deterministic finite truth tables, exhaustive final assessment is possible. Keep its result evaluator-only until the candidate is irrevocably selected. If exhaustive validation is available to the learner, charge all necessary target queries and call the outcome exact finite verification. If validation is noisy or sampled, preregister its acceptance and repeated-testing rule; reusing the same held-out outcomes to select successive candidates invalidates an ordinary fresh-test guarantee.

Use development worlds for debugging and freeze code, parameters, task distributions, and evaluation seeds before held-out assessment. Preserve earlier development failures. A seed that defines a shared predecessor and later-task family is a cluster, not a separate replication for every arm or every challenge. Paired comparisons should respect that structure. A hand-designed witness can establish possibility; held-out worlds estimate behavior within the chosen generator, not outside it.

Inspect useful-reuse and adverse-reuse results separately before any pooled average. Archive effects can reverse with costs and task relatedness. A mean over an arbitrary mixture should not become a universal recommendation.

## Interpretation and review blockers

This experiment can demonstrate that paid transfer of particular construction or inquiry means changes a successor's ability to build another executable function. It cannot establish independent plural purposes if all agents share one supplied objective. Multiple task worlds are not multiple participants with standing. Mention plural access as an untested next requirement unless the implementation actually includes it.

The following would block the intended causal interpretation: future-dependent retention; hidden-target ranking or stopping; predecessor-state leakage; a baseline forbidden from legitimate rebuilding; unequal unreported lifetime resources; free installation after paid discovery; using evaluator truth to select a winner; or treating repeated arm outcomes as independent replications. A fixed primitive grammar, limited horizon, and externally supplied resources are acceptable scope limits when stated honestly.

The pass condition is modest and substantive: **after the first solution and its maker are gone, a paid inheritance policy sometimes preserves executable routes to another construction; an equally funded successor can also overcome or outperform that policy when the inherited means are irrelevant, misleading, or too costly.** That would test the mechanism without defining generative success into the favored arm.

## Addendum: the proposed three-input NAND implementation

The implementation being prepared after this initial audit uses three-input Boolean NAND synthesis, a common deterministic enumerator, paid candidate evaluation and installation, and three or four handoffs. All successors inherit the winning source and can recover its subexpressions. Extra roots are selected using old-task score, behavioral diversity, or recency before the later target is revealed. The proposed task families are one-bit changes, independent functions, and repetitions. Resources carry forward with declared external inflow. This is a suitable bounded test of transferred intermediate constructions; it does not implement the separate laboratory factorial suggested above.

Review these points before interpreting results:

1. **New construction versus direct reuse.** Record whether the new target is already exactly computed by any inherited root or recoverable winner subexpression. With only 256 three-input Boolean functions, a one-bit-changed target can coincide with a retained near-miss. Installing it establishes useful preservation, not a new construction by the successor. Report direct reuse and genuinely new composition separately. Show all-world outcomes alongside any subset where the target was absent from the inherited repertoire.
2. **Transitive source cost.** A root can contain many internal gates. Charge and serialize its dependency closure rather than treating every root as one equal-size object. Shared source can be deduplicated under a stated representation. Log redundant roots already recoverable from the winner; do not count them as independent inherited capabilities.
3. **Cached computation versus empirical evidence.** Known primitives and supplied target truth tables make this synthesis from a specification. A stored truth table saves deterministic evaluation; it is not a noisy experimental finding. A code-only versus code-plus-truth-table ablation can isolate that computational saving if code-only successors can recompute it at the normal price.
4. **No free semantic archive.** A semantic-deduplication map, visited set, shortest-program map, or candidate queue surviving the handoff can transfer the whole search history for free. Reinitialize these from the paid serialized package. Within a generation, allowed bookkeeping can be retained under its declared cost assumption.
5. **Family-specific interpretation.** One-bit-related targets intentionally make old output similarity potentially useful. Independent and repeat families test different conditions. Publish them separately and avoid treating the chosen mixture as a universal future-task distribution.
6. **Failure without fictitious death.** If an unsuccessful new synthesis leaves the old function intact, later rounds should continue under that actual state unless the protocol explicitly models a terminating obligation. A counter of consecutive successes may stop; the simulated organization need not disappear. Censoring after first failure would hide later recovery and impose a stronger failure law than the stated process.

The initial review's concern about hidden-target oracle calls becomes a narrower computation-accounting question when the target truth table is supplied openly. Its concerns about future-dependent retention, source leakage, installed-artifact selection, and lifetime costs still apply unchanged.

## Implementation audit: first inspected model

The first direct inspection covered `experiments/constructive-succession/model.py` with SHA256 `ba733bdc353a6b6b087d9ce23724e130208f39577ed4c130692441e68979df9b` and its accompanying protocol. No model edits were made. This is a scoped AI-assisted code review, not independent human peer review or external validation.

No blocking arithmetic, hidden-target, or predecessor-state error was found in this version. Additional diagnostics ran 360 configurations: five policies, three prices, two flows, three task regimes, and four seeds per combination. Each run checked final-package acyclicity and cache correctness, every episode's independent ledger equation, installed-source transfer cost, and the implication that a newly composed installed function was not an inherited exact match. All passed. Repeated conditions in this check are mechanism repetitions, not independent statistical evidence.

The inspected implementation correctly:

- passes only the current target to the learner and retention functions;
- remaps a fresh package containing the complete dependency closure of retained source;
- reconstructs the successor's semantic dictionary from delivered or newly paid tables;
- allows recovery and use of successful-source subexpressions;
- charges shared extra dependencies once;
- reserves incumbent transfer while searching and requires affordable installation plus new-source transfer before replacement;
- distinguishes direct inherited matching from installation of a newly composed truth function;
- carries balances forward and continues after unsuccessful changed tasks.

Four interpretation or specification corrections remain material:

**Eager recomputation is a policy, not a necessity.** The inspected `episode` evaluates every affordable uncached source node before checking whether the already installed or cached code solves the task. At extra-source price zero and flow 300, the `diverse_recompute` repeat condition spends 128 units reevaluating 16 extra tables in each successor, although the existing XOR already solves the repeated target. The cached diversity arm spends zero on reevaluation. A comparison can faithfully report this fixed eager policy, but cannot call the full difference an unavoidable cost of source-only inheritance. A target-driven or lazy recovery policy could avoid these repeat-task expenses. The current protocol should name the eager step, or implementation should be revised and rechecked.

**Diversity is ranked before affordability.** `choose_roots` constructs its complete max-distance ordering before `handoff` skips unaffordable roots. Its reference set therefore includes some roots that are not actually retained; it also does not immediately incorporate all dependencies retained by an accepted root. The algorithm is a precomputed diversity ordering followed by greedy affordable retention. Describing it as maximally separated from the actually retained functions is stronger than the implemented rule. Narrowing the description is sufficient unless a cost-aware diversity algorithm is intended.

**Source-match and public-primitive match differ.** `inherited_target` includes all public primitives. `solution_target` includes only the installed artifact's dependency closure, which can omit an unused primitive. Consequently `inherited_target and not solution_target` is not, by itself, an extra-archive match: a target equal to an unused public input also satisfies it. Exclude primitive targets or include public inputs in the baseline repertoire before using that difference to attribute direct reuse to the extra archive. The present `new_composition` classification itself does not have this problem.

**Search effects and storage effects must remain separate.** Adding inherited functions changes the initial pair enumeration and can delay productive combinations even when source storage is free. Worse outcomes may reflect a larger proposal queue, retention costs, recomputation costs, or their interaction. The same search routine across arms is appropriate, but does not make library contents causally irrelevant to its order. Explain the measured mechanism using the stage ledger and attempted candidates, not storage price alone.

Relative to the prior experiments, the defensible new object is a repeated paid handoff of actually constructed computational components, with physical code dependencies, cached deterministic evaluations, bank carry, and subsequent construction under changed specifications. It goes beyond one inherited summary or one contextual-policy discovery episode. The supplied NAND semantics, target family, base learner, competence, service pricing, and external work flow remain unchanged boundary machinery; the study does not demonstrate their endogenous reproduction or new evaluative purposes.
